# 08 — Route Coexistence (Sharing a Host with Non-Razy Apps)

A Razy distributor bound to `/` **claims the whole host** at the web-server level, and
once the web server hands a request to `index.php`, PHP never gives it back. That is
fine while Razy owns the host — and it is the reported failure mode the moment a sibling
app (a Python API, a reporting tool, anything) shares the domain under a path prefix.
This page explains the mechanism in plain language, the topologies that work, and the
host-level `exclude_paths` config that makes path-sharing explicit.

Verified sources: `architecture/ROUTE-COEXISTENCE.md` (the evidence dossier; every
failure-mode claim below cites it or the code directly),
`src/asset/setup/htaccess.tpl`, `src/asset/setup/caddyfile.tpl`,
`src/library/Razy/Routing/RewriteRuleCompiler.php`,
`src/library/Razy/Routing/ExcludePaths.php`, `src/library/Razy/Application.php`.

## 1. What "claims the host" actually means

Two independent claims happen on every request, and both must be considered:

**Claim 1 — the web server.** The generated `.htaccess` (machine-owned; regenerated by
`php Razy.phar rewrite`) ends every distributor block with a fallback rule
`RewriteRule ^<mount>(.*)$ %{ENV:BASE}index.php [L]` (`htaccess.tpl:41-47`) that fires
whenever the path is not a real file/dir/symlink and not on the internal-file loop-guard
denylist (`htaccess.tpl:46`). A sibling app reached via `ProxyPass`/alias does **not**
exist as a file under the Razy docroot, so its requests pass the `!-f/!-d/!-l` tests and
land on `index.php`. The Caddy/FrankenPHP output is stricter still: `php_server` is the
last, unscoped handler of every site block (`caddyfile.tpl:46-53`) — per the FrankenPHP
docs it is equivalent to `try_files {path} {path}/index.php index.php`, so *any*
non-file request is claimed host-wide.

**Claim 2 — PHP.** Inside `index.php`, the distributor is picked by longest matching
mount prefix (`Domain::matchQuery`, `Domain.php:122,:143`) and routes match by
prefix: lazy routes are `str_starts_with` against `/alias/route/`
(`RouteDispatcher.php:454`, prefix built in `setLazyRoute` `:244-261`), and standard
routes compile to *un-anchored* regexes whose tail group swallows everything below the
route (`architecture/ROUTE-COEXISTENCE.md` §1.6). A route registered as `'/'` therefore
matches **every** path in the distributor — which is the "lazyRoute and wildcard routes
steal it worse" half of the operator report.

The two claims decompose into the dossier's failure modes; the two you must know:

- **FM-1 (the theft).** Root-mounted distributor + `fallback => true`
  (`Distributor.php:70,:123`) ⇒ every request that is not a physical file becomes a Razy
  request. Details + evidence: `architecture/ROUTE-COEXISTENCE.md` §2 FM-1.
- **FM-2 (the amplification).** Once stolen, the foreign path can be answered `200` by
  the *wrong app* — a module-root lazy route (`/shop/`) swallows `/shop/reports/x`
  because `str_starts_with('/shop/reports/x', '/shop/')` is true. Monitoring that only
  watches for 5xx will not see this. Details: dossier §2 FM-2.

And the corollary that closes the back door: on a total route miss PHP emits its own
404 (`Application::query()` → `Error::show404()`, dossier §1.6) — **there is no
mechanism for PHP to hand a request back to the web server.** Coexistence must be
decided at the web-server layer, which is exactly what the rest of this page does.

## 2. Topology options, ranked

| Topology | How | Razy change needed | When |
|---|---|---|---|
| **Subdomain per app** (default recommendation) | `pyapp.example.com` → its own vhost/site; Razy keeps `example.com` | none — this is the model the code already lives by (per-domain bindings, dossier §3(e)) | always, unless a customer owns one path on a shared apex |
| **Edge proxy, path-split** (recommended for one domain) | nginx/Caddy at the edge routes `/api-py/` → sibling upstream and the rest → Razy; Razy's generated file is used only behind the Razy location | none — edge config is operator-owned (`deploy/README.md:78-80` already deploys this way) | you control an edge proxy |
| **Same web server, declared exclusions** | add `exclude_paths` to `sites.inc.php` (below) so the generated file itself refuses to claim sibling prefixes | Phase 1 support shipped — see §3 | Apache/FrankenPHP is the only lever (shared host, no edge) |
| **Sub-path mount per app (same domain, no edge)** | `php Razy.phar set example.com/app mydist` — Apache already claims per-mount (`{route_path}`); under Caddy the PHP claim is now scoped by an `@php_claimed` matcher | Phase 2 support shipped — see §4 | sharing one domain on Apache or FrankenPHP without an edge proxy |
| ~~Hand-edit the generated `.htaccess`/`Caddyfile`~~ | — | **never** | RZ-013 (`skills/RAZY-AI-RULES.md:332-339`); worse, the checksum watchdog (`Application::validation()` `:688`, regenerate on mismatch `:699-700`) silently erases manual edits at the end of the next request |

Worked configs for the edge topologies (nginx + Caddy, with an ASCII topology diagram)
are in [`deploy/coexistence/`](../deploy/coexistence/README.md).

## 3. `exclude_paths` — declared sibling exclusions

**One new key in `sites.inc.php`, host-level**, beside `domains` and `alias`:

```php
return [
    'domains' => [
        'example.com' => ['/' => 'mydist'],
    ],
    'alias' => [],

    // Sibling applications on this host: prefixes the generated .htaccess /
    // Caddyfile must never claim. Regenerate afterwards: php Razy.phar rewrite mydist
    'exclude_paths' => ['/api-py', '/reporting'],
];
```

*Decision, recorded per the dossier's open question Q1:* the key is **host-level, not
per-distributor** — an exclusion is a statement about sibling apps sharing the host, not
a distributor's own claim, and one declaration must cover every distributor mounted on
it. The same decision is documented in the `Razy\Routing\ExcludePaths` class docblock.
The read path: `Application::loadSiteConfig()` reads the key from `sites.inc.php` and
defaults it to `[]` (`Application.php:379,:425-427`); `updateRewriteRules()`
(`Application.php:514`) and `updateCaddyfile()` (`Application.php:545`) forward it to the
two compilers. `writeSiteConfig()` re-emits it, so `php Razy.phar set` does not erase it.

### What it emits

Apache — one passthrough pair per prefix, emitted **before** the shared rule, the domain
gate, and every distributor block (`htaccess.tpl:7-12`, compiled by
`RewriteRuleCompiler::compileExclusionRules()`, `RewriteRuleCompiler.php:122-130`):

```apache
# Declared sibling prefix /api-py: never claimed by Razy (sites.inc.php 'exclude_paths' — see manual/08-coexistence.md).
# REQUEST_URI carries the full path; per-directory patterns below see the prefix-stripped path.
RewriteCond %{REQUEST_URI} ^/api-py(/|$)
RewriteRule ^ - [L]
```

`%{REQUEST_URI}` is deliberate: per-directory `.htaccess` patterns see the
directory-prefix-**stripped** path
([Apache per-directory rewrites](https://httpd.apache.org/docs/current/rewrite/htaccess.html#path-stripping)),
while `REQUEST_URI` is always the full path — so the condition is correct even when
Razy sits in a subdirectory (in that case the prefix must include the install sub-path:
a Razy install under `/shop` declaring a sibling at `/shop/reports` writes
`/shop/reports`). `[L]` on a `-` target stops this rewrite pass with **no** internal
redirect ([flags doc](https://httpd.apache.org/docs/current/rewrite/flags.html#flag_l));
the request then falls through to normal Apache processing (vhost `Alias`/`ProxyPass`
still required — see §5).

Caddy/FrankenPHP — a `not path` named matcher (`@not_excluded`) that removes the
prefixes from the `php_server` claim, worker and standard modes alike
(`caddyfile.tpl:40-53`):

```
	# Declared sibling paths (sites.inc.php 'exclude_paths') — never claimed by Razy.
	# php_server is gated on @not_excluded, so these paths are served statically if
	# present or 404; proxying them belongs to the edge config (this file stays do-not-claim).
	@not_excluded not path /api-py /api-py/* /reporting /reporting/*
	php_server @not_excluded {
		worker /app/public/index.php
	}
```

*Decision, recorded per the dossier's Q3:* the generator emits **do-not-claim only**.
Proxying the excluded paths would require `reverse_proxy <upstream>`, which would make
Razy's machine-owned file the owner of your app graph. Upstream wiring belongs to the
edge operator (`deploy/coexistence/`). `php_server [<matcher>]` matcher support is the
documented FrankenPHP form
([config docs](https://frankenphp.dev/docs/config/)).

Regeneration is the existing command — `php Razy.phar rewrite <dist>` (Apache) and
`php Razy.phar rewrite --caddy` — so the checksum watchdog stays satisfied
(RZ-013-clean by construction). *illustrative*: the two snippets above are pinned exactly
by `tests/ExcludePathsGenerationTest.php`.

### Validation (fails at generation, not silently)

`ExcludePaths::normalize()` (`ExcludePaths.php:88`) runs at `rewrite` time and throws
`Razy\Exception\ConfigurationException` — with the offending entry named — when a value
is not a list of strings, or an entry:

| Rule | Example rejected |
|---|---|
| must start with `/` and contain only letters/digits/`.`/`_`/`-` per segment | `'api-py'`, `'/api py'`, `'/api\py'` |
| no regex/glob syntax (the value is emitted verbatim into matching rules) | `'/api.*'`, `'/api(/|$)'`, `'/api*'` |
| `'/'` alone (would exclude the whole host) | `'/'` |
| first segment is Razy's own URL space | `'/index.php'`, `'/shared'`, `'/data'`, `'/webassets'`, `'/sites'`, … (`ExcludePaths.php:62-74`) |

Tolerated and normalized: a trailing slash (`/api-py/` ⇒ `/api-py`), surrounding
whitespace, duplicate entries (first occurrence wins). Escaping is minimal and explicit:
dots are backslash-escaped for the Apache condition (`ExcludePaths::apachePattern()`
`:150`) and Caddy globs are built as `prefix` + `prefix/*`
(`ExcludePaths::caddyPaths()` `:164`).

### What `exclude_paths` does *not* do

- **It does not proxy.** The sibling still needs a real handler: `Alias`/`ProxyPass`
  in the vhost, or an edge proxy. Declaring a prefix with no handler turns the theft
  into a plain server-level 404 — honest, but not served (this is the FM-1 inversion).
- **It does not exempt the narrow Razy handlers that sit above the claim**: the global
  `^\w+/shared/` rule (`htaccess.tpl:14`, FM-3, open question Q8), webassets and data
  rules. Do not mount a sibling *under* a path those patterns match (e.g.
  `/anything/shared/...`).
- **It does not touch PHP routing.** FM-2 inside PHP is untouched — the point is that
  excluded requests no longer reach PHP at all on correctly generated files.
- **The fallback denylist (`htaccess.tpl:46`) stays a pure loop-guard** (Q2): its
  accidental exemptions (`/asset-foo` surviving because of `^asset`) remain undefined
  behavior — do not build coexistence on them; declare prefixes.
- Probes: under Caddy, scoped hosts get a dedicated `/_razy/health` handle (Phase 2 —
  see §4), so the liveness probe survives sub-path mounts; Apache hosts and
  `/_razy/metrics` still require a root mount or edge forwarding (FM-5 in the dossier).

## 4. Caddy claim scoping (Phase 2)

Apache claims are per-mount by construction: every block carries the `{route_path}`
prefix (`htaccess.tpl:29,33,41`). The Caddy generator used to trail behind — one
`php_server` tail claimed the **whole host** even when every distributor mounted only
`/app`. It now emits one of three modes per site (`CaddyfileCompiler::compileSiteBlocks()`):

1. **Scoped** — every mount on the domain is a sub-path:

   ```caddy
   @php_claimed {
       path /app /app/*                     # OR-list of the domain's mounts
       not path /api-py /api-py/*           # declared exclusions, absorbed in-matcher
   }
   handle /_razy/health { ... }             # FM-5, below
   php_server @php_claimed                  # worker mode: worker block inside
   ```

   Inside a named matcher, `path` arguments OR together and `not path` ANDs the
   negation — exactly "on one of our mounts, and not excluded". Mount paths are
   validated per segment (word chars/dot/hyphen; empty and dot segments rejected with
   `ConfigurationException`); multi-segment mounts (`/team/app` — legitimate per
   `set.inc.php:60`, consumed Apache-side at `RewriteRuleCompiler.php:202`) scope with
   their full prefix.
2. **Root + exclusions** — a `/` mount claims the whole host by definition, so the
   Phase 1 `@not_excluded` gate stands unchanged.
3. **Root-only, no exclusions** — the legacy bare `php_server`; output is
   **byte-identical** to pre-Phase-2 (goldens re-pinned from the Phase 2 side in
   `tests/CaddyClaimScopingTest`).

Health (FM-5, the answer to dossier Q5): scoped hosts get `handle /_razy/health`
emitted **before** the claim — pattern from `deploy/Caddyfile:132-137`, with
`Cache-Control: no-store` — deliberately standard (non-worker) `php_server`, since
`Razy\Health` answers pre-dispatch and never needs the app worker. Root mounts
already reach the probe through the catch-all, so no block is emitted there.

Regenerate after upgrade (`php Razy.phar rewrite --caddy`); the checksum watchdog
would force it anyway (RZ-013).

## 5. Apache-only coexistence, end to end

For the shared-host operator who owns the vhost (or a host `Include`) but not an edge
proxy — the one combination the generated file alone cannot finish (it can refuse to
claim, but cannot serve the sibling):

```apache
# In the vhost / an Include'd file — operator-owned, never machine-owned:
ProxyPass        /api-py/ http://127.0.0.1:8000/
ProxyPassReverse /api-py/ http://127.0.0.1:8000/
```

plus `sites.inc.php`: `'exclude_paths' => ['/api-py']`, then `php Razy.phar rewrite mydist`.
Order of evaluation that makes this safe: vhost-level `ProxyPass` runs *before*
per-directory `.htaccess` anyway
([Apache "When not to use mod_rewrite"](https://httpd.apache.org/docs/current/rewrite/)),
and the exclusion rule guarantees that anything reaching the Razy ruleset with that
prefix stops there instead of being rewritten to `index.php`. Full worked files:
[`deploy/coexistence/apache-vhost-exinclude.conf`](../deploy/coexistence/apache-vhost-exinclude.conf)
and
[`deploy/coexistence/sites.exclude.php.example`](../deploy/coexistence/sites.exclude.php.example).

## 6. Checklist

```
[ ] Sibling has a real handler (edge proxy location, or vhost Alias/ProxyPass)
[ ] sites.inc.php declares every sibling prefix in 'exclude_paths'
[ ] php Razy.phar rewrite <dist>   (and --caddy under FrankenPHP) — no exceptions thrown
[ ] Generated file contains the passthrough block BEFORE the domain gate / php_server claim
[ ] Requests to /<prefix>/... reach the sibling; a Razy route still serves normally
[ ] Caddy, sub-path-only mounts: Caddyfile shows the @php_claimed matcher and the
    /_razy/health handle; /_razy/health answers even though no distributor owns /
[ ] No hand-edit of .htaccess / Caddyfile anywhere (RZ-013 + watchdog)
```
