# 01 — Getting Started

Install the framework, create a distributor, ship your first module end-to-end, and serve it.
Every command and file shape here was verified against the repo at writing time.

---

## Requirements

| Requirement | Value | Source |
|---|---|---|
| PHP | **8.2+** | `composer.json` `"php": "^8.2"`; build check at `src/system/terminal/build.inc.php` |
| Extensions | `ext-zip`, `ext-curl`, `ext-json` | `composer.json` `require` |
| Recommended | Composer (dev tooling only — Razy has **zero runtime deps**) | `composer.lock`: 0 production packages |

## Install paths

### A. Composer library (you build an app on top of Razy)

```bash
composer require rayfunghk/razy
```

Package name/PSR-4 map verified in [`composer.json`](../composer.json) (`"rayfunghk/razy"`,
`"Razy\\": "src/library/Razy/"`). Note: this gives you the classes; you still run the CLI
through `Razy.phar` (the repo ships a prebuilt one at the root; `bin` entry declared in
`composer.json`).

### B. From source (you want your own binary)

```bash
git clone https://github.com/RayFungHK/Razy && cd Razy
php build.php              # builds Razy.phar from src/ (needs phar.readonly=0)
```

`build.php` is the repo-root phar builder (see [`readme.md`](../readme.md) Quick Start line 1).
If PHP refuses phar writing: `php -d phar.readonly=0 build.php`.

### C. Prebuilt phar

`Razy.phar` is committed at the repo root (tracked in git; rebuilt on releases). Copy it next
to your project. `php Razy.phar version` prints the version.

## The CLI, honestly

The quick-start block in [`readme.md`](../readme.md) is the right *shape* but names one
command that does not exist. Verified reality (`src/system/terminal/`, 27 command files):

- **There is no `init` command.** Project scaffolding is `build`; site (distributor)
  creation is **`set ... -i`** (`set.inc.php:13-20` — `-i` "Initialize the distributor
  folder with dist.php", generating it from `src/asset/setup/dist.php.tpl` at
  `set.inc.php:82`).
- `src/system/terminal/help.inc.php` is itself stale (lists `fix`, `man`, `commit`,
  `query`, `update` which have no command file).

The real minimal sequence:

```bash
php Razy.phar build .                    # 1. set up the Razy env here: config.inc.php,
                                         #    sites.inc.php, index.php, .htaccess,
                                         #    repository.inc.php  (build.inc.php:3-11)
php Razy.phar set localhost mysite -i    # 2. bind a domain to a distributor code and
                                         #    initialize sites/mysite/dist.php
php Razy.phar set example.com mysite     #    ...and a real domain later (same dist code)
# 3. put modules under modules/<vendor>/<module>/, list them in sites/mysite/dist.php
php Razy.phar compose mysite             # 4. resolve composer-style deps into autoload/
php Razy.phar validate mysite            # 5. verify the distribution
php Razy.phar rewrite mysite             # 6. (re)generate webserver rewrite rules
php Razy.phar serve --dist mysite        # 7. dev server, default localhost:8080
```

`serve` verified options (`src/system/terminal/serve.inc.php:23` usage block):
`-l <host:port>` (default `localhost:8080`), `--dist <code[@tag]>` (forces multisite),
`--fqdn <domain[/path]>` (simulated host, default `serve.razy.local`), `--standalone`,
`--open`, `--worker`/`-w` (auto-restart worker), `--max-requests <N>` (default 500).

Other commands you'll actually use: `runapp <dist>` (interactive shell),
`routes`/`inspect <dist>` (debug routing/config), `run <fqdn+path>` (execute a route from
CLI), `install <owner/repo>` (module from GitHub — read the trust caveat in
[06](06-packages-and-deployment.md) first), `pack`, `pkg`, `publish`, `cache`, `queue`,
`scaffold`, `standalone`, `sync`, `link`/`unlink`, `remove`, `search`, `bridge`,
`generate-skills`, `version`, `help`.

## Project layout

After `build .` you get (templates: `src/asset/setup/`; sample on disk: `playground/`):

```
yourproject/
├── index.php              # front controller (loads Razy.phar)
├── config.inc.php         # global config (below)
├── sites.inc.php          # domain → distributor mapping
├── .htaccess              # rewrite rules (regenerated by `rewrite`)
├── repository.inc.php     # package-manager endpoints (packagist/github/custom)
├── Razy.phar              # the framework binary
├── sites/
│   └── mysite/
│       └── dist.php       # per-distributor config (below)
├── modules/
│   └── <vendor>/<module>/ # your local modules (or shared/module + vendor/module)
├── autoload/
│   └── <dist>/            # per-distributor composer-style vendor dir — NEVER edit (RZ-007)
└── data/                  # runtime data (per-domain-dist folders; getDataPath() roots)
```

**`config.inc.php`** (from `src/asset/setup/config.inc.php.tpl`, verified against
`playground/config.inc.php`):

```php
<?php
return [
    'debug'         => false,
    'multiple_site' => false,
    'phar_location' => '/app',   // where Razy.phar lives
    'timezone'      => 'UTC',
];
```

**`sites.inc.php`** — domain map; the shipped template (`src/asset/setup/sites.inc.php.tpl`)
documents: string value = distribution path; array value = advanced; `'path' => 'mysite@v2'`
selects a **tag** from dist.php; a `/path` key serves the same dist from a subdirectory;
`alias` maps alternate domains. Per-domain config-folder mapping lives in `config_mapping`
inside `dist.php` — **not** here.

**`sites/<dist>/dist.php`** — the distributor manifest (sample verified on disk:
`playground/sites/appdemo/dist.php`):

```php
<?php
return [
    'dist'            => 'mysite',
    'global_module'   => false,
    'autoload_shared' => false,
    'greedy'          => false,   // true = load every module folder present
    'strict'          => false,
    'modules' => [                // tag => { module_code => version-tag }
        '*' => [
            'data/database_demo' => 'default',
        ],
        'beta' => [
            'data/database_demo' => 'default',
        ],
    ],
    // 'config_mapping' => ['beta' => 'v2'],  // config folder per site tag (readme Routing)
    // 'reserve'        => ['api'],            // site-level segments; see Agent::reserve
];
```

Key meanings verified: `modules` nested tag map drives `@tag` selection
(`sites.inc.php.tpl` comment + `serve --dist code@tag`); `greedy` loads all folders;
`reserve` is referenced by `Agent::reserve()` (`src/library/Razy/Agent.php:435`:
"declared in dist.php `reserve`").

## First module, end-to-end

File shapes below are copied from the working demos
(`demo_modules/data/database_demo/`): a module root with `module.php`, and one **version
directory** (`default/`) holding `package.php`, `controller/`, `view/`.

### 1. Module identity — `modules/acme/hello/module.php`

```php
<?php
return [
    'module_code' => 'acme/hello',
    'name'        => 'Hello',
    'author'      => 'You',
    'description' => 'My first module',
    'version'     => '1.0.0',
];
```
(shape: `demo_modules/data/database_demo/module.php:14-20`; code format `vendor/package`
enforced by `validate`)

### 2. Dependencies & API code — `modules/acme/hello/default/package.php`

```php
<?php
return [
    'name'        => 'Hello',
    'version'     => '1.0.0',
    'author'      => 'You',
    'description' => 'My first module',
    // 'api_name'     => 'hello',                            // ModuleInfo.php:238
    // 'require'      => ['acme/shared' => '^1.0'],          // MODULE dependency (code => constraint)
    //                                               //   ModuleInfo.php:250-263
    // 'prerequisite' => ['monolog/monolog' => '^2.0'],      // external package constraint;
    //                                               //   compose resolves into autoload/
    //                                               //   (ModuleInfo.php:227-235; RZ-007)
];
```
(shape: `demo_modules/data/database_demo/default/package.php:4-9`; `api_name` parsed at
`src/library/Razy/ModuleInfo.php:238`; require/prerequisite → [06](06-packages-and-deployment.md))

### 3. Main controller — `modules/acme/hello/default/controller/hello.php`

The main controller file is named after the module short name (`database_demo.php` in the
demo) and **returns an anonymous class**:

```php
<?php
namespace Razy\Module\hello;

use Razy\Agent;
use Razy\Controller;

return new class extends Controller {
    public function __onInit(Agent $agent): bool
    {
        // Lazy routes: key = URL under /acme/hello/, value = closure path (NO .php suffix!)
        // 'main' has no slash → resolves to controller/hello.main.php (class-name prefix);
        // 'demo/insert' has a slash → controller/demo/insert.php  (ClosureLoader.php:117-130)
        $agent->addLazyRoute([
            '/'      => 'main',
            'health' => 'health',
        ]);
        return true;   // returning false marks the module Failed (Controller.php:79)
    }
};
```
(shape + `__onInit` verified against
`demo_modules/data/database_demo/default/controller/database_demo.php:37-83`)

### 4. Page handler — `.../controller/hello.main.php`

Handler files are plain closures; `$this` is the controller:

```php
<?php
use Razy\Controller;

return function (): void {
    /** @var Controller $this */
    header('Content-Type: text/html; charset=UTF-8');
    $source = $this->loadTemplate('main');     // view/main.tpl (Controller.php:353,382-390)
    $source->assign(['site_name' => 'My Site']);
    echo $source->output();
};
```
(pattern: `demo_modules/core/template_demo/default/controller/template_demo.main.php:10-22`)

### 5. JSON handler — `.../controller/hello.health.php`

Use the `xhr()` **object factory** (it is not a static sender):

```php
<?php
use Razy\Controller;

return function (): void {
    /** @var Controller $this */
    $this->xhr()
        ->responseAsBody(['ok' => true, 'route' => $this->getRoutedInfo()['route']]);
};
```

`$this->xhr(): XHR` — `Controller.php`. `responseAsBody(array)` **emits** (headers +
your `responseCode()` + JSON) and ends dispatch: the internal `output()` unwinds the
dispatch stack via the same `HttpException` control-flow the readiness 503 rail uses,
so a later `echo` never runs. (Since v1.2 this is one call: the older two-step
`responseAsBody()` + `sendEnvelope()` chain only shipped bodies when BOTH were called —
no call site in the wild ever got that right; `sendEnvelope()` survives as an
idempotent no-op / array-mode pull.) Full XHR surface: [03](03-routing-and-requests.md).

### 6. View — `.../view/main.tpl`

```html
<h1>{$site_name}</h1>
<p>Hello from Razy. Missing value: {$missing|"fallback"}</p>
```

`{$x|"fallback"}` is a **fallback chain** (verified semantics), not a modifier pipe — see
[05](05-templates.md) before using `|` for anything else.

### 7. Register + run

Add `'acme/hello' => 'default'` under the `'*'` tag in `sites/mysite/dist.php`, then:

```bash
php Razy.phar compose mysite && php Razy.phar validate mysite
php Razy.phar serve --dist mysite     # http://localhost:8080/acme/hello/  (with --fqdn default)
```

Debug a blank 404 with `php Razy.phar routes mysite` and `php Razy.phar inspect mysite`.

## Subdirectory installs (`http://host/abc/`)

Verified in `src/system/bootstrap.inc.php`:

- `RELATIVE_ROOT` (`:123`) — URL path from the web root to the install (e.g. `abc/`); used
  for `RAZY_URL_ROOT`, `getAssetPath()`, and `REQUEST_URI` parsing (`:90-92` docblock).
- `RELATIVE_COOKIE_PATH` (`:126`) — cookie path follows the install root.
- `RAZY_URL_ROOT` (`:136`) — the effective site URL root.

To serve from a path, bind `domain/path` in `sites.inc.php` (the template shows the
`'/path' => 'dist'` form) or pass `--fqdn domain/path` to `serve`; `rewrite` regenerates
rule files. If assets 404 after moving installs, re-run `php Razy.phar rewrite <dist>`.

## Common pitfalls

1. **Looking for an `init` command** — it doesn't exist; use `build` + `set -i` (above).
2. **Template `|`** — it is fallback, not a pipe of modifiers (`Template/Entity.php:388-396`).
   Modifiers are `->name:arg`. The demo `.tpl` files use legacy `|` forms; don't copy that.
3. **`$this->xhr()->responseAsBody(...)` without `sendEnvelope()`** — silent empty body.
4. **Editing `autoload/` by hand** — RZ-007; edit `package.php` and re-`compose`.
5. **Expecting an auto-connected database** — the framework does not connect for you; you
   explicitly `connect()` (demo pattern) or resolve a `Database` — see [04](04-database.md).
6. **Cross-module `require`** — RZ-001. Only `addAPICommand` + `api()`, events, and gated
   bridge commands cross a module.
7. **Static state in worker mode** — your module classes stay loaded across requests; see
   [03 §worker mode](03-routing-and-requests.md).
8. **Raw user data in templates** — no auto-escape (RZ-004); [05](05-templates.md).
9. **`php Razy.phar bridge …` on a shared host** — unauthenticated local IPC; treat shell
   access as full API access ([07](07-security-guide.md) §bridge).
10. **Trusting `documentation/` HTML** — legacy generator output; trust `manual/` + code.
