# OFFICIAL-REPO-INSTALL — Making a GitHub Repo the Razy Official Pack Repository

Research + gap analysis + spec proposal. Code beats docs: every claim cites `path/File.php:line`.
Companion tone doc: `architecture/PORTING-VALUE.md`. Generated 2026-07. Status: **complete**.

## 1. Pack anatomy today

### 1.1 What a "pack" IS

A **pack** is a *versioned, distributable artifact* published into a package repository
(the `packages/` tree is the reference layout a remote repo must mirror). Two flavors exist:

| Kind | Example | Identity | Runs as |
|---|---|---|---|
| **Module pack** | `packages/demo/demo_index/` | `module_code` `vendor/module` (`demo/demo_index`) | Module inside a distributor (via `install`/RepoInstaller) |
| **Standalone package** | `packages/dashboard/` | `package_name` (`dashboard`), index `"type": "package"` (`packages/index.json:13`) | Own process via `pkg` command (`mode: serve`, healthcheck) — `Razy\Package\PackageRunner`, registry `Razy\Package\PackageRegistry` (`src/library/Razy/Package/PackageRegistry.php:22-37`) |

Contrast (who consumes what):

| Artifact | Definition location | Consumer |
|---|---|---|
| Plain module | `shared/module/<vendor>/<mod>/module.php` or `sites/<dist>/...` (resolved by `pack` at `src/system/terminal/pack.inc.php:112-117`) | The framework runtime directly; never versioned/published |
| **Pack** (module phar / standalone) | `packages/` tree + remote repo mirror | `PackageManager` + `RepoInstaller` (§2), `pkg` command for standalone (`PackageRegistry.php:102-114` scans dir packages; `PackageManifest.php:81-94` reads `razy.pkg.json` from **inside the phar root**) |
| Composer package | `package.php` `require`/`prerequisite` | `php Razy.phar compose` → `autoload/` (machine-owned, RZ-007); a **separate channel** from packs |

### 1.2 Repository file layout (what a repo must serve)

```
packages/
├── index.json                      # registry aggregate: every pack, one key each
├── demo/demo_index/                # module pack
│   ├── manifest.json               # full release history
│   ├── latest.json                 # version pointer {version,file,checksum}
│   └── 1.0.0.phar                  # artifact
└── dashboard/                      # standalone package pack
    ├── manifest.json
    ├── razy.pkg.json               # runtime manifest (also embedded in phar)
    └── 1.0.0.phar
```

From `packages/index.json:1-19` — keyed by pack id (`vendor/module` or bare `package_name`):

| Field | Required? | Evidence | Notes |
|---|---|---|---|
| `description` | yes (observed) | `packages/index.json:3,11` | free text |
| `author` | yes (observed) | `packages/index.json:4,12` | empty string tolerated (`:12`) |

### 1.4 Per-pack metadata files

- **`manifest.json`** (per pack) — full release registry. `packages/demo/demo_index/manifest.json:1-19`:
  `module_code` (or `package_name` for standalone, cf. `packages/dashboard/manifest.json:2`),
  `description`, `author`, `latest`, `versions[]`, `updated`, and
  `releases.<version>` each with `{file, size, checksum, created, php_version, razy_version}`
  (`packages/demo/demo_index/manifest.json:10-18`). `checksum` = SHA-256 of the phar
  (written by `pack` via `hash_file('sha256', …)`, `src/system/terminal/pack.inc.php:265,279`).
- **`latest.json`** — quick pointer `{version, file, checksum}`
  (`packages/demo/demo_index/latest.json:1-5`; written by `pack.inc.php:274-282`).
  **Drift**: `packages/dashboard/` has **no** `latest.json` (only `manifest.json` + phar) —
  pointer file is generated by `pack` but was not regenerated for dashboard.
- **`razy.pkg.json`** — standalone-package *runtime* manifest only (not a module field set):
  `package_name, version, description, mode` (`"serve"`), `strict`, `on_depend[]`,
  `healthcheck {url,interval,timeout,start_period}`, `prerequisite {}`
  (`packages/dashboard/razy.pkg.json:1-15`; schema documented at `src/system/terminal/pkg.inc.php:44`,
  parser `src/library/Razy/Package/PackageManifest.php:19-68`).

### 1.5 `packages/publish.inc.php` — build? sign? upload?

`packages/publish.inc.php:8-11` is **only a credentials/config file**: `return ['token' => 'github_pat_…', 'repo' => 'RayFungHK/razy-demo-index']`.
It builds nothing, signs nothing. The pipeline is elsewhere:

- **Build**: `php Razy.phar pack <module_code> <version> [out]` — creates GZIP phar
  (`--no-compress`, `--no-assets` opts, `pack.inc.php:18-20`), requires `phar.readonly=0`
  (`:80-84`), writes `manifest.json` + `latest.json` with SHA-256 (`:265,274-282`).
- **Publish**: `php Razy.phar pkg publish` (standalone `publish` command removed —
  `src/system/terminal/publish.inc.php:10-11`). Helpers there already do GitHub
  tags/releases/**release-asset uploads**: `githubCreateTag` (`:97`), `githubPutFile`
  via Contents API (`:241-243`), `githubCreateRelease` (`:313-342`),
  `githubUploadReleaseAsset` (`:362-371`), `githubGetReleases` (`:405`), `githubDeleteFile` (`:169`).
- **Sign**: **none.** No signature/openssl step exists in pack/publish; only SHA-256 checksums.

> **SECURITY FINDING (live)**: the header of `packages/publish.inc.php:6` says
> *"DO NOT commit this file to version control!"* — yet the file **is committed** at
> `packages/publish.inc.php:9` with a real `github_pat_…` fine-grained PAT in plaintext.
> Before any repo goes "official", revoke + rotate that token and gitignore the file.

## 2. Repo sync + install internals

### 2.1 Class map (the three "managers" are different channels)

| Class | Real role | Source |
|---|---|---|
| `Razy\RepositoryManager` | **Pack-repo channel**: registry of repo URLs, fetch `index.json`/`manifest.json` over raw HTTP, resolve download URL | `src/library/Razy/RepositoryManager.php` |
| `Razy\RepoInstaller` | **Source-zip installer**: GitHub zipball / branch-tag zip / custom ZIP → extract to target | `src/library/Razy/RepoInstaller.php` (alias `Razy\GitHubInstaller`, `:878`) |
| `Razy\PackageManager` | **Composer-compatible library channel** (Packagist/Satis metadata, PSR-4 extraction, `autoload/lock.json`) — the RZ-007 `compose` flow, NOT packs | `src/library/Razy/PackageManager.php:11-16,147` |

> **Doc-drift note**: the brief and other docs call `PackageManager` the "pack" manager;
> code shows pack discovery is `RepositoryManager` and pack *artifact* install is inline in
> `install.inc.php`. `PackageManager` = composer-libs only.

### 2.2 How a repo source is added

- Repositories are a plain PHP map `['https://github.com/owner/repo' => 'main']` loaded from
  **`SYSTEM_ROOT/repository.inc.php`** (`RepositoryManager.php:66-70`; same file re-read by
  `install.inc.php:165,747`). Runtime-only add via `addRepository($url,$branch)`
  (`RepositoryManager.php:144-148`). No git clone anywhere; no "repo add" CLI command exists.
- Index/manifest fetch = **raw HTTP GET**, GitHub web URL rewritten to
  `raw.githubusercontent.com/{owner}/{repo}/{branch}/…` (GitLab variant too),
  `buildRawUrl` (`RepositoryManager.php:382-412`), `fetchIndex` (`:167-194`), `getManifest`
  (`:278-298`). `httpGet` (`:452-467`) sets **no** `CURLOPT_PROTOCOLS` / HTTPS guard.
- Artifact URL (`getDownloadUrl` → `buildReleaseAssetUrl`, `:308-371`): GitHub **Releases
  asset** convention `https://github.com/{o}/{r}/releases/download/{vendor}-{module}-v{ver}/{ver}.phar`
  (`:350-367`); non-GitHub fallback = raw URL `{repo}/{vendor}/{mod}/{ver}.phar` (`:370`).
- Version resolution from pack repo is **index-only** (`latest` field; `stable` is an alias
  of `latest`, `:320-326`). The GitHub *releases* API is used only by `RepoInstaller`
  (`getLatestRelease :203-240`, `getStableRelease :247-289`, `getAvailableTags :296-333`).

### 2.3 The two install paths today (`install.inc.php`)

**Path A — direct repo: `php Razy.phar install owner/repo[@ver] [--latest|-s|--version=|--branch=|--token=]`**
(`install.inc.php:563-870`) → `new RepoInstaller(...)` (`:616-673`) → `validate()`
(`:677`) → `install()` → resolve URL (`RepoInstaller.php:528-581`: release `zipball_url`
or `archive/refs/tags|heads/{x}.zip`) → stream download to temp (`:619-690`) →
`extractArchive` **ZIP** (`:699-779`) → copy to `SYSTEM_ROOT/modules/{name}` or
`sites/{dist}/modules/{name}` (`install.inc.php:582,587`). Installs **raw source tree**, not a phar.

**Path B — pack from registry: `php Razy.phar install vendor/module --from-repo`**
(`install.inc.php:163-561`) → `RepositoryManager` index lookup (`:195-204`) → optional
`disclaimer.txt` display + mandatory `terms.txt` acceptance (`:283-329`) → target prompt
shared vs dist (`:233-276`) → `getDownloadUrl` (`:345`) → **cURL the .phar** (`:369-387`) →
`new Phar($tempPhar)->extractTo($targetPath)` (`:405-406`) into
`shared/module/{vendor}/{mod}` or `sites/{dist}/{vendor}/{mod}` (`:356,360`) → reads
installed `module.php` and offers to recursively install `require` deps (`:429-558`;
dep versions are **ignored**, always `latest`, `:494,817`).

### 2.4 Zip-slip guard — verified CALLED, but not everywhere

`Razy\ArchiveSafety` (`src/library/Razy/ArchiveSafety.php`, born of 2026 audit §S2, `:13-26`)
provides `validateEntryName` (`:41-74`: absolute/drive/`..`/`.`/NUL/control-chars/wrapper
schemes), `validateArchive` (pre-extract enumeration, `:82-103`), `findSymlinks`
(`:111-131`), `isSecureUrl` (HTTPS-only default, `:158-177`), `purgeDirectory` (`:183-205`).

Call sites (complete inventory, `grep 'ArchiveSafety::' src/`):

| Guarded path | Call site |
|---|---|
| RepoInstaller ZIP download | `RepoInstaller.php:625` (`isSecureUrl`, opt-out `PackageManager::$allowInsecureTransport` / `RAZY_ALLOW_INSECURE_TRANSPORT=1`, `:624`) |
| RepoInstaller ZIP extract — **the repo-install call site** | `RepoInstaller.php:719` — `validateArchive($zip)` **before** `extractTo` (`:729`); `findSymlinks` post-extract (`:740`); `purgeDirectory` on reject (`:723,:743`) |
| PackageManager ZIP extract | `PackageManager.php:256,258` (sanitize + `isSecureUrl`), `:298` (`validateArchive`), `:316-318` (`findSymlinks`+purge) |

**Gap**: Path B's phar extraction (`install.inc.php:405-406,538-539`) is **not** covered by
`ArchiveSafety` (it only models `ZipArchive`) and its download curl allows `CURLPROTO_HTTP`
(`:373-374`) with no `isSecureUrl` check. Also the *index/manifest* fetch
(`RepositoryManager.php:452-467`) has no transport guard. Unit-tested:
`tests/ArchiveSafetyTest.php` (per class docblock `:26`).

### 2.5 Integrity today: checksum exists in metadata, verified **nowhere**

- Producer side: `pack` writes SHA-256 into `manifest.json`/`latest.json`
  (`pack.inc.php:265,279` — `hash_file('sha256', $pharFile)`).
- Consumer side: `install --from-repo` never fetches `manifest.json` checksum and never
  hashes the downloaded phar before `new Phar()` (`install.inc.php:369-406`); RepoInstaller
  has no checksum concept. `size`/`checksum` in the release map (`packages/demo/demo_index/manifest.json:13-14`)
  are **decorative** on the install path.
- Code-execution note: install `require`s the just-downloaded `module.php` to read deps
  (`install.inc.php:431,739`) — a malicious phar executes PHP during install regardless of hashing.

### 2.6 BridgeSignature ≠ pack integrity

`Razy\BridgeSignature` is HMAC-SHA256 over cross-distributor **bridge call payloads**
(`src/library/Razy/BridgeSignature.php:53-73`), gated by operator secret
`RAZY_BRIDGE_SECRET` (`:32-39`), enforced in `Module::executeBridgeCommand` (docblock `:13-16`),
constant-time verify + 60s window (`:80-94`). It proves *runtime peer identity*, not artifact
provenance. Grep `openssl_sign|openssl_verify|sodium_crypto` across `src/`: **zero hits** —
no asymmetric signing primitive exists anywhere in the framework; BridgeSignature's
`canonicalPayload`-style deterministic canonicalization (`:53-65`) is the closest prior art
to reuse for manifest signing.

### 4.1 Where repo URLs live (three scopes, all `include`-able PHP — no JSON/env registry)

| Scope | Path | Shape | Loaded by |

### 4.2 Does an "official repo" concept exist? — a *proto-concept*, and it's currently dead

- `build` scaffolds `repository.inc.php` for every new project from the phar asset
  (`src/system/terminal/build.inc.php:89,93` → `src/asset/setup/repository.inc.php`),
  seeded with **`https://github.com/RayFungHK/Razy-Repository/` @ `master`**
  (`src/asset/setup/repository.inc.php:26-27`).
- **Verified 404**: `https://github.com/RayFungHK/Razy-Repository` returns HTTP 404 today
  (public URL fetch, 2026 session). A fresh `php Razy.phar build .` therefore ships users a
  registry URL that resolves to nothing — first `search`/`install --from-repo` fails with
  "not found in configured repositories" (`install.inc.php:198-204`).
- The maintainer's *dev* checkout points elsewhere: root `repository.inc.php:8` →
  `https://github.com/RayFungHK/razy-demo-index/` @ `main` — the same repo as the leftover
  credentials target (`packages/publish.inc.php:10`).

### 4.3 How the existing `packages/` artifacts were produced (workflow forensics)

- **`demo/demo_index/1.0.0.phar` + `manifest.json` + `latest.json`** — built by
  `php Razy.phar pack demo/demo_index 1.0.0`: manifest gets `module_code` + per-release
  `{file,size,checksum,created,php_version,razy_version}`
  (`pack.inc.php:247-269` — exactly the fields in `packages/demo/demo_index/manifest.json`),
  plus the `latest.json` pointer (`:274-282`). Its own footer told the author to
  "Commit packages/ to your repository" and run `publish` (`:292-294`) — the then-standalone
  command, later merged into `pkg publish` (`src/system/terminal/publish.inc.php:10-11`,
  guard message `src/main.php:386-388`).
- **`dashboard/1.0.0.phar`** — built by `pkg publish --scan`, which packs any
  `packages/<name>/` dir having `razy.pkg.json` and no `module.php`
  (`pkg.inc.php:727-733,755-791`), then rewrites `manifest.json` (`:939-948`, note it
  hardcodes `'type' => 'package'`, `:943`) and `index.json` (`:952-958,980-985`).
  `latest.json` is *not* generated by the pkg path — hence its absence for `dashboard` (§1.4 drift).
- **`packages/publish.inc.php`** (token + `RayFungHK/razy-demo-index`) is an **orphan**: no
  code loads it (`grep publish.inc.php` — only the *other* file, the helper library
  `src/system/terminal/publish.inc.php`, is required, `pkg.inc.php:658`); it's a leftover of
  the removed standalone `publish` command, and `pkg publish --push` today demands
  `packages/publish.json` instead (`pkg.inc.php:672-683`).

### 4.4 Live remote state vs local mirror (doc-drift, material)

`https://raw.githubusercontent.com/RayFungHK/razy-demo-index/main/index.json` (fetched, HTTP 200)
currently lists `demo/demo_module` (latest 1.0.1) and `demo/helper_module` — **none** of the
two entries in this repo's `packages/index.json:2-18` (`demo/demo_index`, `dashboard`).
The local `packages/` tree and the pushed registry have diverged; neither is "the" index.
This confirms: index.json is *served from the repo's git tree* (raw URL), while phars are
*served from GitHub Releases* (`RepositoryManager.php:350-367`) — a two-plane repo layout already.

## 5. Vision gap analysis

Vision: *"a GitHub repo becomes the Razy official repository; users one-click install
whichever pack they want."* Current evidence from §1–§4; every "current" cell is code-verified.

| # | Capability | Current state (evidence) | Required for vision |
|---|---|---|---|
| G1 | Zero-config discovery of official repo | New builds get a **404'ing** registry URL (`src/asset/setup/repository.inc.php:27`); everything needs a hand-written `repository.inc.php` (`install.inc.php:165-174`) | Built-in default official repo constant + resolution order CLI > project > default; scaffold points at a live repo |
| G2 | True one-click (`install <pack>`) | Path B works only after config file exists + prompts (F1–F5, §3.2) | `php Razy.phar install demo/demo_index` with no prior setup; `-y` semantics kept |
| G3 | Artifact integrity (tamper) | SHA-256 produced at build (`pack.inc.php:265,279`) but **never verified** at install (`install.inc.php:369-406`; `pkg.inc.php:590-622`) | Fetch release metadata, rehash artifact, hard-fail on mismatch |
| G4 | Publisher authenticity | Trust = "whoever can push to the repo branch"; **no signing primitive exists** (grep `openssl_sign/verify|sodium` = 0 hits) | Signed index (or per-release digest manifest) with pinned verification key; verify before install |
| G5 | Transport security | ZIP path enforces HTTPS w/ opt-out (`RepoInstaller.php:624-629`), but **index fetch** (`RepositoryManager.php:452-467`) and **phar download** paths allow `CURLPROTO_HTTP` (`install.inc.php:373`, `sync.inc.php:294`, `pkg.inc.php:595`) and skip `isSecureUrl` | Route all fetches through one guarded client calling `ArchiveSafety::isSecureUrl` (`ArchiveSafety.php:158-177`) |
| G6 | Version pinning + update UX | Pin = edit `sites/<dist>/repository.inc.php` + `sync` (`sync.inc.php:22-29`); installed-version probe `require`s installed `module.php` (`:236-239`); no lockfile of installed packs | `installed.lock.json` inventory + `update`/`pin` commands; no code-eval to read a version |
| G7 | Rollback | None — `Phar::extractTo(..., true)` overwrites in place (`install.inc.php:406`, `sync.inc.php:325`) | Keep downloaded phars per version (`pkg install` already does, `pkg.inc.php:615-622`) + re-extract-from-cache rollback |
| G8 | Uninstall | No command removes a pack (`help.inc.php` has no uninstall; `remove` = sites, `:34`) | `uninstall <pack>` driven by lock inventory of extracted files |
| G9 | Dependency resolution | `module.php['require']` constraints **ignored** — always installs `latest` (`install.inc.php:494,817`); no recursive cycle guard | Reuse constraint matcher (`PackageManager::versionMatches`, `PackageManager.php:554`) for pack deps |
| G10 | Framework/PHP floor gating | `php_version`/`razy_version` recorded at build only (`pack.inc.php:267-268`), never enforced | Install-time gate on `framework_min` / `php_min` |
| G11 | Extraction safety on the pack path | Zip-slip + symlink guards only on ZIP flows (`RepoInstaller.php:719,740`; `PackageManager.php:298,316`); **phar** extract path unguarded (`install.inc.php:405-406`, `sync.inc.php:324-325`, `pkg install` keeps phar = fine) | Validate `Phar` entry names with `ArchiveSafety::validateEntryName` before extraction; reject stub-exec-capable metadata surprises |
| G12 | Trust labeling (official vs community) | Index has no trust/origin/signed-by concept (`packages/index.json` schema, §1.3); all repos equal (`RepositoryManager.php:203-236`) | `trust: official|community`, origin-pinned repo per pack, shown in prompt |
| G13 | Revocation / yank | `githubDeleteFile` exists (`publish.inc.php:169`) but install has no "yanked" concept | `yanked` flag in release metadata + refuse/warn |
| G14 | Hygienic publish pipeline | Live PAT committed at `packages/publish.inc.php:9` against its own "DO NOT commit" header (`:6`); push is a dev-workstation op (`pkg publish --push`) | GitHub Actions + scoped/short-lived token; `publish.json` gitignored; CI rebuilds + re-signs |
| G15 | Offline/mirror resilience | Every op needs network (index = raw HTTP); no local cache of index | Cache last-good index + per-version phar cache; mirror via `--from <url>` |

Ranking of blockers for "one-click from official repo": **G1 → G2 → G3/G5** (correctness of
trust), then G6/G7 (lifecycle), then G4/G12/G14 (governance).

## 6. Proposed official-repo spec

### 6.1 GitHub repo layout (two-plane repo — the planes already exist, §4.4)

```
RazyHQ/official-repo/                 # one GitHub repo = the registry
├── index.json                        # plane 1: served raw (RepositoryManager.php:176 expects ROOT index.json)
├── index.sig                         #   optional detached signature over canonical index.json (G4)
├── keys/official-repo.pub            #   pinned signing public key (also baked into Razy.phar asset)
├── PUBLISHING.md · LICENSE           #   human governance surface
├── {vendor}/{module}/manifest.json   #   per-pack release registry (fetched at {code}/manifest.json,
│                                     #   RepositoryManager.php:289; pushed today via Contents API, pkg.inc.php:1017)
└── GitHub Releases                   # plane 2: artifacts — tag `{vendor}-{module}-v{X.Y.Z}` (fixed by
                                      #   RepositoryManager.php:353), asset `{X.Y.Z}.phar` (:354,361-366)
    └── assets: 1.2.0.phar [+ optional 1.2.0.phar.sha256]
```

Rules: git tree = mutable metadata (branch pin, e.g. `main`), Releases = immutable artifacts.
Keep today's tag/asset convention byte-identical so `buildReleaseAssetUrl`
(`RepositoryManager.php:350-371`) keeps working unchanged. `dashboard`-style level-0 packs
keep bare-name keys (matches `pkg.inc.php:840-843`).

### 6.2 Extended `index.json` (schema v2, additive — v1 readers ignore unknown keys)

```json
{
  "schema": 2,
  "demo/demo_index": {
    "description": "…", "author": "…", "latest": "1.0.0",
    "versions": ["1.0.0"],
    "type": "module",
    "trust": "official",
    "origin": "https://github.com/RazyHQ/official-repo",
    "releases": {
      "1.0.0": {
        "asset": "1.0.0.phar",
        "url": "https://github.com/RazyHQ/official-repo/releases/download/demo-demo_index-v1.0.0/1.0.0.phar",
        "sha256": "f13c…7e0b", "size": 13199,
        "framework_min": "0.5.0", "php_min": "8.2",
        "yanked": false
      }
    }
  }
}
```

| New field | Why | Replaces/fills |
|---|---|---|
| `schema` | reader/writer negotiation | — (today: none) |
| `trust`, `origin` | trust labeling + origin pinning (G12) | flat trust (§2.2) |
| `releases.<v>.url`/`asset` | explicit artifact locator instead of tag-name magic (F8) | derived `buildReleaseAssetUrl` (`RepositoryManager.php:350-367`) — kept as v1 fallback |
| `releases.<v>.sha256`/`size` | promote existing **decorative** fields (`packages/demo/demo_index/manifest.json:13-14`) into the *index* the installer must verify | per-pack `manifest.json` mirror |
| `framework_min`/`php_min` | install-time gate (G10) | build-time-only stamps `pack.inc.php:267-268` |
| `yanked` | refuse install/`warn` on upgrade (G13) | — |

Per-pack `manifest.json` keeps its `releases` map (already sha256+size shaped,
`pack.inc.php:261-269`); v2 just mandates: installer *must* fetch and verify it, and
`pkg`/`pack` writers must keep index and manifest checksums identical (single writer = CI).

### 6.3 Security posture — honest ledger

| Layer | Verified **today** | Must-add | Notes / prior art |
|---|---|---|---|
| Transport | HTTPS-only **on ZIP download only** (`RepoInstaller.php:625`, env opt-in `:624`) | Same guard on index/manifest/phar fetch (`RepositoryManager.php:452-467`, `install.inc.php:369-376`, `sync.inc.php:290-298`, `pkg.inc.php:591-599`) | `ArchiveSafety::isSecureUrl` (`ArchiveSafety.php:158-177`) is the shared primitive already |
| Origin | none — any repo URL trusted once listed; `getModuleInfo` first-match-wins (`RepositoryManager.php:247-265`) | reject downloads whose final host ≠ pinned `origin` (GitHub redirects to `objects.githubusercontent.com` — allowlist suffix, `CURLOPT_REDIR_PROTOCOLS` already set) | new; small |
| Artifact checksum | **never** (metadata-only, §2.5) | `hash_file('sha256')` vs `releases.<v>.sha256`, hard fail | producer side exists (`pack.inc.php:265`); consumer = ~10 lines per download site |
| Publisher signature | **none** — framework has *zero* asymmetric crypto: `openssl_*` appears only as AES-256-CBC symmetric encrypt/decrypt (`src/library/Razy/Crypt.php:45-89`); no `openssl_sign/verify`, no `sodium_*` (grep = 0) | optional (phase-2): verify `index.sig` with pinned pubkey *before* trusting any checksum; trust model = "GitHub write access" until then — say so in docs | prior art to mirror: canonicalization `BridgeSignature::canonicalPayload` (`:53-65`), constant-time `hash_equals` (`:93`), env-gated enable pattern (`:42-45`) — HMAC ≠ provenance; use `sodium_crypto_sign_*` if ext-sodium present, else `openssl_verify` (RSA/ECDSA) — new code, ~1 class `PackageSignature` |
| Extraction | zip-slip + symlink rejection on ZIP paths (`RepoInstaller.php:719,740`) | per-entry `validateEntryName` over `Phar` iteration before `extractTo`; keep phar-as-file installs (`pkg install`) as the safer default | `ArchiveSafety.php:41-74` |
| Install-time code exec | install `require`s downloaded `module.php` to read deps (`install.inc.php:431,739`) | parse dep list from the *signed* index/manifest metadata instead of executing code | design debt; signature makes it acceptable but metadata makes it clean |
| Signing authority hygiene | live PAT committed in-git (`packages/publish.inc.php:9`) | revoke/rotate now; CI publish via Actions + OIDC/short-lived token; `.gitignore` `packages/publish.json` | §3.5 |

Honest bottom line: a *checksum* only binds artifact→publisher-intent; only the
*signed index with a pinned key* binds publisher→intent. Ship checksum first (kills
mirror drift + accident), signature second (kills repo-compromise), and document the
interim trust anchor as exactly "GitHub account `RazyHQ`" — not "verified".

## 7. One-click UX + trust matrix

### 7.1 Resolution order for `install` (proposed; no `--from-repo` flag needed)

```
php Razy.phar install demo/demo_index                 # 1-click: registry lookup
php Razy.phar install demo/demo_index@1.0.0 -y        # pinned + non-interactive
php Razy.phar install dashboard --from https://github.com/acme/packs@main   # one-shot override
php Razy.phar install https://example.com/mod.zip …   # unchanged Path A (URL form, RepoInstaller)
```

1. `--from <url>[@branch]` — this command only (feeds `RepositoryManager::addRepository`,
   `RepositoryManager.php:144-148`); nothing persisted.
2. `arg` contains `://` → **today Path A** kept (`RepoInstaller`, §2.3).
3. Project `repository.inc.php` entries (§4.1).
4. **Built-in default official repo** — constant in the phar (e.g.
   `Razy\Package\Registry::DEFAULT_OFFICIAL = https://github.com/RazyHQ/official-repo @ main`),
   env `RAZY_REGISTRY` overrides; replaces the dead scaffold seed (§4.2, G1).
5. If not found anywhere *and* arg looks like `owner/repo` → fall back to Path A GitHub repo
   with an explicit "not in registry; installing raw source from GitHub" notice — preserves
   every today-usage (`install owner/repo`, `install.inc.php:563+`) at the cost of ambiguity
   between org names and pack vendors (open question Q2, §8).

Internals: `install <vendor>/<mod>` keeps Path B's pipeline but (a) verifies sha256 vs signed
index before touching disk, (b) stores the phar in `packages/cache/`, (c) writes
`packs.lock.json`. Same verification inserted in `pkg install` (`pkg.inc.php:590-622`) and
`sync` (`sync.inc.php:287-325`) so one trust rule governs all three.

### 7.2 Lifecycle UX

| Command | Behavior | Backed by |
|---|---|---|
| `install X` (again) | lock says already installed → no-op + `update` hint | new `packs.lock.json` |
| `install X@1.2.0` | switch versions (verify → backup → extract → lock) | `--force` today blindly reinstalls (`pkg.inc.php:558-563`) |
| `update [X]` | resolve index `latest` → verify → swap; refuses if `pinned` | replaces "edit config + sync" (§3.4) |
| `pin X` / `unpin X` | freeze at lock version / release to `latest` | `sites/*/repository.inc.php` pin concept, promoted (`sync.inc.php:202`) |
| `rollback X[@v]` | re-extract cached phar (checksum re-verified) | cache from `pkg install` pattern (`pkg.inc.php:615-622`) |
| `uninstall X` | delete paths recorded in lock `files[]` | none exists (G8) |
| `repo add/list/remove` | manage `repository.inc.php` (plus `--trust`) | none exists (F1) |

### 7.3 Trust matrix

| Source | Today's anchor | v2 phase-1 (checksum) | v2 phase-2 (+signed index) |
|---|---|---|---|
| Built-in official repo | GitHub account write access, unverified download | + artifact matches index sha256 | + index signed, pinned key in phar |
| Project `repository.inc.php` entry | same | + checksum vs its own index (self-consistent only) | + per-repo key if publisher signs |
| `--from <url>` community repo | same; **operator opted in this run** | + checksum, origin host pinned to that URL's host | warn loudly when unsigned: author/type echoed (cf. `install.inc.php:209-214`), terms gate kept (`:300-328`) |
| Mirror / local path | `isSecureUrl` treats scheme-less as local-safe (`ArchiveSafety.php:160-163`); ftp/sftp allowed (`:174-176`) | checksum becomes the *only* integrity line — mandatory, not optional | signature carries across mirrors unchanged — the only mirror-safe anchor |

Scenarios:
- **Malicious/compromised repo**: phase-1 a tampered phar fails checksum *unless* the attacker
  also edits the index (same repo = same write access → **not** prevented; document honestly).
  Phase-2 index signature makes tampering impossible without the signing key; unsigned index ⇒
  hard "UNVERIFIED registry" banner, never silent.
- **Registry offline**: last-good index + phar cache allow `install X@<cached>` with
  "offline: serving cached 1.0.0" + refusal for anything uncached; mirror host via `--from`
  (checksum still enforced; signature still verified).
- **Yanked version**: new installs refused (`yanked` flag, §6.2); `rollback`/cached reinstall
  allowed with warning — matches npm/crates.io semantics users already know.
- **Rollback**: extract from cache = deterministic since cache checksum re-verified each use;
  no network dependency.
