# Razy v1.1.0-beta.1 — Migration Governance, Permissions Module, Honest Audit

**Release Date:** September 2026  
**PHP:** 8.2+

The release that turned two architecture dossiers into shipped behaviour:
migration governance M0–M4 (scope, checksums, the `migrate` CLI, deploy
declarations, O(1) fast path) and the complete `razymod/permissions` module
line S1–S5 (auth seam, RBAC schema, check surface, `{@can}` templates,
opt-in cache + audit). Two doc-phantoms died (`getSharedInstance`,
`Configuration->get()`), one published module was repaired retroactively,
and every gate decision is on the record. 14 commits, 5,365 tests.
No breaking API changes; the two behaviour changes are migration-scoped and
maintainer-decided (below).

## Changed / Migration notes

- **Migration tracking is now scoped + checksummed** (M0+M1). The shared
  `migrations` table gains `scope` and `checksum` columns by self-healing
  `ADD COLUMN` on existing installs. After upgrading, run
  `php Razy.phar migrate <dist> --status` once: pre-M1 rows have empty
  checksums (unverifiable by design, never guessed) — a clean `--status`
  means your history is intact; drift lines name the exact edited/missing file.
- **Bulk `migrate <dist>` only runs `deploy`-declared modules** (M3): modules
  whose `package.php` omits `'migration'` keep the historic manual behaviour
  (name them explicitly to apply). This is the deliberate inversion of
  "nobody ever migrated" → "web requests never migrate, deploy does".
- **`razymod/permissions` is published to the official registry** at 0.2.0
  (signed index). Consumers declare it in `package.php` `require` (RZ-007);
  its tables arrive via `migrate` (it declares `migration => 'deploy'`);
  the fail-closed wiring is `demos/golden/policy` + `manual/11-permissions.md`.
