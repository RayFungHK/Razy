# Razy v1.2.0 — The Security Release (and the One That Fixed What the Bench Found)

**Release Date:** September 2026
**PHP:** 8.2+ (8.5-ready, matrix-pinned; floor raises to ^8.3 after upstream 8.2 EOL 2026-12-31)

The release the manual had already been advertising as "v1.2+" — the day the label and the
constant met. Four rail lines closed and one performance epoch earned its numbers honestly:
the armed CSRF door (`'csrf' => 'on'` as the whole authoring surface, on a session that
finally owns its cookie), deploy-time boot snapshots with measured receipts and a
host-foreign artifact the shortening itself could not skip, module lifecycle from derived
readiness to the token-gated wizard door, and validation's first real consumer — whose door
test caught that the family's JSON emission had shipped empty-bodied since birth. Underneath:
worker-mode status integrity, persistent-connection resurrection, and the CI-hygiene rot that
had hidden a queue bug for months finally cleared. Suite 5,441 → 5,565 (+124 tests). No
breaking API changes; every behaviour change is disclosed below.

## Highlights

- **Added** COMPILE-ON-DEPLOY (M1 + M2), the deploy-time boot snapshot — default-off,
  opt-in per dist (dossier: `architecture/COMPILE-ON-DEPLOY.md`). M1: `build.php` bakes
  an authoritative classmap into the phar; `autoload()` answers phar-library lookups
  from one array read where the legacy ladder paid `is_dir` + up to 3 `is_file` probes
  per class — probe-neutral by construction (misses and failed hits fall through).

  `__onInit` declaration table (routes with their precomputed regexes, API/bridge
  commands, bindings, listeners/observers, module middleware) into
  `data/compiled/<dist>@<tag>.php`; dists carrying `'compiled_boot' => true` replay
  it at boot (fpm kills the per-request assembly; worker cuts thread boot). Guards,
  all fail-toward-today's-boot: closure/await/shadow-route registrations REFUSE
  compilation with every offender named; the command boots twice (determinism) and
  then boots the compiled path itself and refuses if the replay diverges; a stat
  fingerprint (mtime+size of every dist `.php`, the trust level worker mode already
  uses) auto-degrades to the full boot, loudly, when stale. `__onInit` is not re-run —
  legal under RZ-009's declaration-purity, and `__onLoad`/`__onRequire` still run live.

  `compile --standalone=<path>` covers standalone apps — with no dist.php to hold
  a flag, the artifact's existence IS the opt-in (deleting it is the revert);

  the app folder (config.inc.php excluded — runtime config is read live around
  the replay), and a loadModule-injected (PackageRunner) co-module graph takes
  the whole boot legacy rather than replaying half a graph. The fpm benchmark
  image ships `ARG COMPILED=1` (deploy-time compile baked in; `=0` rebuilds the
  pure legacy baseline for A/B). Live-verified: benchgate compiles,
  replays with `4 routes match`, artifact 5.3 KiB. **Published

  invisible; dev keeps full stats) — median **+1.23** vs legacy, never lost a
  pair, TRUST no longer needs declaring. First shipping build of the gate

  STATUS array is FLAT (`opcache_enabled`; the nested tree is get_CONFIGURATION)

- **Fixed** `Database` persistent-link death — a MySQL link idle past `wait_timeout`
  dies server-side while PDO's pool hands the DEAD handle back; every later query threw
  2006 "MySQL server has gone away" **forever**, and a worker process outlives every
  idle timeout (live-caught by the benchmark worker; production ERP workers hold the
  same overnight shape — zero reconnect/ping machinery existed anywhere). `execute()`
  now distinguishes link death (2006/2013/lost-connection wording) from query errors:
  `driver->reconnect()` (MySQL forces a FRESH non-persistent link — asking the pool for
  persistent again may draw another corpse) and ONE retry of the statement. The subtle
  half is resynchronization: `Database`'s adapter reference, the prepared-statement pool
  AND the `Transaction` wrapper all cache the old PDO link — all three rebuild or the
  retry dies identically (proved by fault-injection: real MySQL, `KILL` the connection
  mid-session, next query succeeds on a new connection id). Raw direct-adapter callers
  outside `execute()` are not retried — the shared door carries the traffic.

## Behaviour changes (all disclosed)

- CSRF: `'csrf' => 'on'` in `dist.php` arms the door; `validate` prints **UNARMED** guidance
  on dists without the key (today's behaviour, loudly neutral); `csrfToken()/csrfField()`
  THROW with the fix on unarmed dists; `Route::csrfExempt()` **throws at registration** on an
  empty reason; rejections answer 419 (JSON for XHR, HTML otherwise) and fire `csrf.failed`.
- `razymod/queue-admin` 1.2.x: mismatch is the door's 419 (was handler-level 403); an UNARMED
  dist makes the admin surface THROW instead of running mutations unprotected.
- `Session::start()` now adopts a valid carried cookie id; mint/rotate/destroy emit cookies
  (caller `setId()` still wins — BC).
- Compiled boot is fully opt-in (`'compiled_boot' => true` per dist / standalone artifact
  existence); every guard fails TOWARD the full boot, loudly (`STALE`/`FOREIGN` error_log).
- Module route readiness gates are explicit opt-in (`Route::ready()`, `readyRoutes()`);
  a not-ready gate answers 503 (deploy-provision) or 302 into `/__setup/` (wizard-provision),
  never silent 404. `module wizard-token` mints single-use 10-minute tokens.
- `module.installed` fires only on a non-empty migration apply (CLI and wizard alike).
- Status codes ride `header('HTTP/1.1 N', true, N)` framework-wide; worker-mode module code
  doing the same after a status was set shares the documented `http_response_code()` fate.
- `Controller::validated()` rejects with 403 (no-rule-set) or 422 `{error:"validation-failed",
  errors,fix}` and ends dispatch via HttpException — rejected input cannot reach handlers.
- `XHR::responseAsBody()` emits directly (the forgotten `sendEnvelope()` tail is an
  idempotent array-mode pull now); eight first-party call sites revived, zero module edits.
- MySQL link death (2006/2013) triggers one transparent reconnect+retry through
  `Database::execute()`; raw direct-adapter callers are not retried.
- Worker multisite boots the `'*'` default site (the `UNKNOWN` host sentinel is collapsed);
  `'*'` is now an acceptable `sites.inc.php` key; the stock template comment tells the
  array-form-only truth.

## Upgrade notes

- **From any 1.x:** nothing to do to keep running byte-identically. Every new door is
  default-off/default-unarmed.
- **To arm CSRF (the point of this release):** set `'csrf' => 'on'` in `dist.php`,
  `php Razy.phar validate <dist>` should print `✓ armed`, add `csrfField()` to forms (or the
  `<meta>` + `X-CSRF-TOKEN` header recipe, manual/07 §4), declare exemptions as
  `->csrfExempt('<reason>')` on `Route` entities. Audit your mutating surface first with
  `tools/csrf-surface-audit.php <site-root> <dist>` (read-only, runs under your current phar).
- **To adopt compiled boot:** upgrade the phar, run `php Razy.phar compile <code>` on
  staging, compare `--status`, then set `'compiled_boot' => true`. Refusals name every
  offender; deletion of the artifact (or `--clear`) is the instant revert.
- **`razymod/queue-admin` users:** the module now REQUIRES an armed dist to serve writes;
  its controller files were renamed to the loadable class-name form (a prior-layout install
  that could not load it anyway is unaffected).
