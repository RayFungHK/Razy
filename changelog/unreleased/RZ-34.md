# RZ-34: Razy.phar builds are reproducible

## Fixed
- `php build.php` added `src/` in directory order and stored each file's mtime,
  so two builds of the same tree were not the same bytes. Files are collected
  in sorted path order (regular files, including hidden ones; not directories
  or symlinks — the same set `Phar::buildFromDirectory` adds). Every entry is
  stamped with `SOURCE_DATE_EPOCH` when that value is digits, otherwise the
  git commit time of `HEAD`, otherwise 0. The stub, the `Razy.phar` alias,
  gzip compression and the SHA256 signature are fixed. The classmap is still
  `ksort`ed. Library files are scanned in path order, so the first declaration
  of a class does not depend on directory order.

## Changed
- Phar bytes change for an unchanged source tree. Consumers re-pin.
