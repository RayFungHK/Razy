# RZ-15: in-process HTTP test client

## Added
- `Razy\Testing\Client`: runs web requests through a real dist inside the test process (PHPUnit or
  any CLI runner). `new Client(array $sites, string $host = 'localhost', int $port = 80, bool $https
  = false)` where `$sites` maps URL paths to dist codes, as `sites.inc.php` does for one host.
  Methods: `get()`, `post()` (form), `postJson()` (any method), `request()`, `withHeader()`,
  `withCookie()`, `cookies()`, `session()` (by reference). Each request boots the dist afresh, sets
  the superglobals and the raw body, and restores them afterwards. Cookies set by a response go into
  the jar, and `$_SESSION` is kept between requests.
- `Razy\Testing\TestResponse`: `status()`, `body()`, `header()`, `headers()`, `json()`,
  `isRedirect()`, `cookies()`.
- `Razy\Http\Headers`: the framework's one door to response headers. `send()`, `status()`, `remove()`,
  `sent()`, `cookie()` call PHP's `header()`, `http_response_code()`, `header_remove()`,
  `headers_sent()` and `setcookie()`, or record while a capture is active (`startCapture()`,
  `stopCapture()`, `isCapturing()`).
- `Razy\RuntimeMode`: `isWeb()`, `isCli()`, `isSimulatedWeb()`. They answer from `WEB_MODE` /
  `CLI_MODE` unless the test client is running a request.
- `Razy\Http\RequestBody::raw()` (the request body; `FormRequest::fromJson()` and `jsonArray()` use it).

## Changed
- Framework code sends headers through `Razy\Http\Headers` instead of calling `header()` directly:
  auth/authz/CSRF/rate-limit middleware, route redirects and the module-readiness answers, error
  pages, `Response`, `SecurityHeaders`, `StaticFile`, `XHR`, `Controller::goto()`, and the session
  cookie. Outside a capture, behaviour is unchanged.
- The route table, `__onRouted` vs `__onScriptReady`, session start, security headers, error pages
  and `Response::send()` ask `RuntimeMode` instead of reading `WEB_MODE`/`CLI_MODE` directly. The
  setup wizard keeps its hard `CLI_MODE` refusal.

## Not covered yet
- `/_razy/health`, `/_razy/metrics` and SSE streams still call `header()` directly, and so do
  headers a module sends with PHP's `header()`. The test client does not see them.
