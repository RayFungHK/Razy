# RZ-10: security headers and a per-request CSP nonce from dist config

## Added
- `Razy\Http\SecurityHeaders`, configured by dist.php `'security_headers'` and validated at
  boot (unknown keys, bad header names, CR/LF in values and bad HSTS options throw
  `ConfigurationException`). Keys: `csp` (string, or `[directive => source(s)]`; `{nonce}` is
  replaced by the request's nonce), `csp_report_only`, `frame_ancestors`, `referrer_policy`,
  `hsts` (max-age, or `['max_age', 'include_subdomains', 'preload']`; sent over HTTPS only),
  `headers` (`[name => value]`; `false` removes a header).
- A fresh CSP nonce per request (worker mode included). Templates read it as `{$csp_nonce}`;
  code reads `Distributor::getCspNonce()`. `Distributor::getSecurityHeaders()`.

## Changed
- Every response from a dist now carries the baseline unless the dist opts out with
  `'security_headers' => false`: `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN` and
  `Content-Security-Policy: frame-ancestors 'self'`. The baseline restricts framing only; it
  does not limit scripts, styles or connections. A site framed by another origin needs
  `'frame_ancestors' => "'self' https://portal.example.com"` (or `false`).
- 404 and exception pages send the dist's headers too (the baseline when no dist has booted).
