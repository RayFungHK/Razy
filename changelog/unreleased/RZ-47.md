# RZ-47: security follow-ups of RZ-41

## Security
- `SimpleSyntax::parseParens()` throws `Razy\Exception\SyntaxException` on a stray `)` or an unclosed `(`. Before, a
  stray `)` silently dropped everything parsed so far and an unclosed `(` was read as if closed. The query builder
  turns it into a `QueryException` for Where, ORDER BY (`order('>id)--')` used to drop the whole ORDER BY), Update
  Simple Syntax and JOIN syntax; `WhereSyntax::VerifySyntax()` reports it as invalid (`''`). Version ranges
  (`VersionUtil`) and template `{@if}` conditions, both developer-written, now fail loud with `SyntaxException`.
- `Statement::order()`: a parenthesised group as a sort key is a `QueryException` (was a `TypeError`).
- `ModelQuery::bulkUpdate()`: each SET value is bound to its own reserved placeholder (`_mq_set_N`). Bound as
  `:column`, a `where()` parameter of the same name replaced the value being written.
- A JSON path containing a NUL byte is refused (`PDO::quote()` truncates at NUL).
- `ParameterBinder::paramsUsedIn()` counts `:rzpN` only outside quoted literals and quoted identifiers; PDO skips
  those, so a placeholder-like text inside `'...'` bound a value with no placeholder.
- `Model::firstOrCreate()` / `firstOrNew()` / `updateOrCreate()` (via `firstByAttributes()`) and
  `Model::increment()` / `decrement()` validate the keys / column they splice into Simple Syntax as single
  identifiers (`QueryException` otherwise).

## Changed
- `Crypt::encrypt()` / `decrypt()` / `needsReencrypt()` throw `InvalidArgumentException` for an empty key; it was
  aliased to `"\0"`, which protects nothing.

## Compatibility
- A syntax string with unbalanced parentheses throws where it used to be silently rewritten. A caller relying on
  an empty Crypt key must pass a real secret.
