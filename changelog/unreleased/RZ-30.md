# RZ-30: `{@if}` does not re-parse a substituted value

## Security
- `{@if}` ran `parseText` on the body, then `parseText` again on the chosen branch. A value containing `{$…}` or `{@…}` was executed as template. The condition is still parsed once, as a plain value. The body is split on its own `{@else}` before substitution, and only the chosen branch's function tags run. The caller substitutes `{$…}` once, so those characters are text.
- `{@def}` assigns the parsed value and does not render it. `{@repeat}` repeats the raw body and the caller substitutes once. Neither re-parses a substituted value. They are unchanged.

## Migration
- A template that stored template syntax in a value and expected `{@if}` to execute it now prints that syntax. That execution was the injection.
