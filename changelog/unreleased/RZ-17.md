# RZ-17: fail fast on a malformed `sites.inc.php`

## Added
- `Razy\Config\SiteConfig::validate(mixed $config, string $file): array` checks what
  `sites.inc.php` returned and fills in missing `domains` / `alias` / `exclude_paths` with `[]`.
  `SiteConfig::SHAPE` (the expected-shape message) and `SiteConfig::DIST_IDENTIFIER` (the
  `code[@tag]` pattern, now shared with `Application::updateSites()`).

## Changed
- `Application::loadSiteConfig()` (the only reader of `sites.inc.php`: web boot and every CLI
  command) throws `Razy\Exception\ConfigurationException` naming the file and
  "sites.inc.php must return ['domains' => [...], 'alias' => [...]]" when:
  - the file returns a non-array (no `return` gives int 1, which used to be a `TypeError` that
    never named the file);
  - `domains`, `alias` or `exclude_paths` is set but not an array (silently replaced by `[]` before);
  - a domain value is not an array (e.g. `'example.com' => 'main'`, silently dropped before);
  - a dist entry is not a string or nested array, or not in `code[@tag]` form (silently dropped
    before);
  - an alias target is not a string.
- A parse error (or any other `Throwable`) in `sites.inc.php` is wrapped in a
  `ConfigurationException` with the file path. Before, only `Exception` was wrapped.
- Entries that are skipped are now logged through `Error\ErrorReporter::warn()`: a host key that
  is not a valid domain, an invalid alias pair, a dist with no `dist.php`. They are still skipped,
  not fatal.
- Web requests still show only the generic error page; the detail goes to the log. CLI commands
  print the message.

## Migration
- A file that relied on bad entries being dropped silently now stops at boot. Fix the entry it
  names: turn `'host' => 'dist'` into `'host' => ['/' => 'dist']`, and remove dead entries.
