# RZ-02: real parameter binding

## Changed
- `Database::execute()` no longer interpolates values. It compiles the statement into an SQL
  template with named placeholders (`:rzp0`, `:rzp1`, ...) and binds the values. Strings,
  booleans and JSON are bound; NULL and numbers stay inline (no quoting risk).
- Booleans bind as `PDO::PARAM_BOOL` on Postgres and as integer 0/1 on MySQL and SQLite.
  Writing `true` into a Postgres `boolean` column now works (it failed with
  "column is of type boolean but expression is of type integer").
- The statement pool is keyed on the SQL template, so one query shape is prepared once
  whatever the values.
- JSON operands (`~=`, `@=`, `|=` on non-columns, `CAST(... AS JSON)`) are bound instead of
  escaped with a MySQL-only backslash rule.
- LIKE patterns (`*=`, `^=`, `$=`) escape backslashes as well as `%` and `_`; on SQLite the
  clause carries `ESCAPE '\'`, since SQLite has no default escape character.

## Added
- `Statement::compile(): array{sql: string, params: array<string, mixed>}`.
- `Statement::interpolate(array $compiled): string` renders a compiled statement as literal
  SQL for logs. `Statement::literal($value)` gives the driver-aware literal (Postgres booleans
  are `TRUE`/`FALSE`). `Statement::sqlValue($value)` is the builder hook.
- `Database::getStatementPool()`.
- `Razy\Database\ParameterBinder`.
- CI: `postgres-integration` job runs the binding suite against a Postgres 16 service.

## Compatibility
- `Statement::getSyntax()` still returns literal SQL (debug form), so callers that log it or
  feed it to `createViewTable()` see no change, except that Postgres booleans now render as
  `TRUE`/`FALSE`.
- `getQueried()` / `getLastQueried()` still record literal SQL.
- Raw statements (`$db->prepare('SELECT ...')`) run unchanged and nothing is bound for them.
