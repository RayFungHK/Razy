# RZ-52: a "0" token or a 0 key is data, never the end of the input

## Fixed
- `ArrayUtil::refactor()` skipped every key from `0` on: `array_keys()` of a list starts with the integer `0`, which
  ended the `while ($key = array_shift(...))` loop, so `refactor([['a', 'b'], ['c', 'd']])` returned `[]`.
- `Collection` filters: a selector segment `"0"` ended the path, so `$collection('0.n')` returned the whole
  collection instead of the first item's `n`, and `$collection('0')` returned nothing.
- `VersionUtil::vc()`: a `"0"` clip ended the parse, so the requirement `0` matched no version (`vc('0', '0.0.0')`
  was `false`).
- Template `{@if}`: a `"0"` operand inside a group is evaluated instead of ending the loop. No output changes
  (`null` and `false` both pick the `{@else}` branch).

The query-builder sites of the same idiom were fixed in RZ-47.
