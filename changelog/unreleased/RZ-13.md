# RZ-13: readiness checks and `GET /_razy/ready`

## Added
- `Razy\Health\HealthRegistry`: named readiness checks. A check returns true (or nothing) when its
  dependency is usable, and returns false or throws when it is not. `register($name, $check,
  $critical = true)`, `remove()`, `has()`, `names()`, `run()`. Failures are logged through
  `Error\ErrorReporter::warn()`.
- `$agent->addHealthCheck(string $name, callable $check, bool $critical = true)` adds a check to the
  dist's registry as `<module code>:<name>` (`Module::addHealthCheck()`,
  `Distributor::getHealthChecks()`, `Standalone::getHealthChecks()`). Register in `__onLoad` when the
  dist uses `compiled_boot`.
- `GET /_razy/ready` (relative to the dist's URL path) runs the dist's checks and answers JSON
  `{"status":"ok|degraded|fail","checks":{name:{status,critical,duration_ms}},"timestamp":…}`:
  503 when a critical check fails, 200 otherwise (`degraded` = only non-critical checks failed).
  It is answered after the modules load and before the session and the route table, so a probe
  never opens a session or runs a route. Check errors are included only with
  `?token=<RAZY_HEALTH_TOKEN>`.
- `Health::READY_PATH`, `Health::isReadyPath()`, `Health::readiness()`, `Health::respondReady()`.

## Unchanged
- `GET /_razy/health` stays a pre-boot liveness probe and still always says `ok`.
- A dist with no checks answers `/_razy/ready` with 200 `ok`. The path was previously routed like
  any other path; a route registered at `/_razy/ready` is now shadowed by the probe.
