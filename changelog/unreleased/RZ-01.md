# RZ-01: production-safe error handling

## Changed
- The web exception page shows only the heading and an **error id** unless debug is on.
  Message, file, line, SQL, console and stack trace appear only in debug mode, and every
  value is HTML-escaped (headings included). The page also sends an `X-Error-Id` header.
- Every web exception is logged server-side via `Error::report()` before the page renders.
- `QueryException` no longer appends the SQL to `getMessage()`; the SQL is available from
  the new `QueryException::getSql()`. Code that parsed SQL out of the message must switch
  to `getSql()`.
- Worker mode (FrankenPHP) re-applies the `debug` config at the start of every request;
  previously `Error::reset()` left debug off from the second request on.

## Added
- `Error::report(Throwable $e, array $context = []): string` logs message, file, line, SQL
  and trace and returns the error id. `Error::setLogger(?LoggerInterface)` picks the logger
  (default: PHP `error_log()`).
- `RAZY_DEBUG` environment override: a falsy value forces debug off anywhere; a truthy value
  turns debug on only for loopback requests (loopback host name **and** loopback
  `REMOTE_ADDR`) and is refused (logged once) elsewhere.
- `ErrorRenderer::render(Throwable, string $errorId): string` renders the page without sending it.

## Compatibility
- `ErrorConfig::configure(array $config, ?array $server = null)` and
  `QueryException::__construct(..., ?string $sql = null)` gain optional trailing parameters;
  existing calls keep working.
- Apps that showed a user-facing message through `new Error($message)` in production must
  move that text into the heading (third constructor argument) or render their own page.
