# RZ-39: the bootstrap locale setup is safe under threaded SAPIs

## Fixed
- `bootstrap.inc.php` called `setlocale(LC_CTYPE, 'C.UTF-8', 'en_US.UTF-8', 'UTF-8', '')` on
  every request. Under a threaded SAPI (FrankenPHP, any ZTS server) the locale is process-wide,
  and PHP resets it at the end of every request that called `setlocale()` (`LC_ALL=C`, then
  `LC_CTYPE=C.UTF-8`). Another thread could then read `LC_CTYPE=C`, so `escapeshellarg()` and
  other locale-dependent calls dropped non-ASCII bytes. Under FrankenPHP with 8 threads, a
  thread reading LC_CTYPE in a loop saw `C` (musl) and a corrupted name (glibc) while other
  threads served requests. The bootstrap now changes LC_CTYPE only when it is not already the
  target. PHP 8.2+ starts every request in `C.UTF-8` where the system has it, so with the
  defaults no `setlocale()` runs and nothing is reset. Once applied, a process does not apply it
  again (worker mode, a second bootstrap).

## Added
- `Razy\Util\Locale`: `ensureUtf8Ctype(string|false $env, array $config = [], ?callable
  $setlocale = null): string|false`, plus `candidates()` and `isTarget()`.
- `RAZY_LOCALE_CTYPE` (env) and config.inc.php `'locale_ctype'` (the env wins): a list of
  LC_CTYPE candidates tried in order (comma list or array; `env` = the environment's locale), or
  `off` to never touch the locale. Unset = `C.UTF-8`, `en_US.UTF-8`, `UTF-8`, the environment's
  locale, and any UTF-8 LC_CTYPE already in effect is kept. With a configured list, only a listed
  name counts as set (codeset spelling ignored: `C.utf8` = `C.UTF-8`).
- `tools/frankenphp-locale-race.sh` and the CI job "Threaded SAPI locale": classic FrankenPHP
  (glibc and musl images), one thread watching LC_CTYPE while others serve requests. The
  pre-RZ-39 call must show the race (the check bites); the RZ-39 call must not.

## Changed
- The locale setup runs after `.env` and config.inc.php load (it reads `'locale_ctype'`), right
  before the trusted-proxy setup. Nothing between the old and new place depends on LC_CTYPE.

## Migration
- None for the defaults. A process whose LC_CTYPE is not UTF-8 at start still gets the first
  available candidate, and PHP still resets that at request end. Under a threaded SAPI, start the
  process in a UTF-8 locale or set `RAZY_LOCALE_CTYPE=off`.
