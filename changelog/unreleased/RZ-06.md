# RZ-06: request-scoped principal, 401 vs 403, pluggable denial renderer

## Added
- `Razy\Authz\Principal` (id + attribute bag) and `Razy\Authz\Identity`, the dist's
  request-scoped principal. One module registers the resolver with
  `$agent->identity(fn (array $context): ?Principal => …)`; it runs at most once per request
  (the Authz middleware resets it at the start of every request, and a cached principal from an
  earlier request is dropped even before that, so worker mode never carries a principal into the
  next request). A throwing resolver counts as signed out.
- `Controller::principal(): ?Principal`; `Identity` is bound on the dist container.
- `Distributor::getAuthzIdentity()`, `Distributor::getAuthzDenial()`.
- dist.php `'authz' => ['login_url' => '/login']` (local path only; validated at boot).
- `$agent->onAuthzDenied(fn (Refusal $r) => …)` replaces how the dist renders refusals.
  `Razy\Authz\Refusal` carries `status` (401/403), `ability`, `undefined`, `unauthenticated`,
  the routed `context` and `loginUrl`. One module owns the renderer.

## Changed
- With a resolver registered, a signed-out request on a `Route::can()` route is refused **401**
  before any ability runs (HTML GET/HEAD: 302 to `login_url?next=<request URI>` when set; JSON:
  `{"error":"unauthenticated","login":…}`). Signed in but refused stays 403. Without a resolver
  nothing changes.
- Ability predicates receive `$context['principal']`.
- The default 401/403 HTML pages no longer name the module, route or ability; an undefined
  ability is reported in the error log instead. The JSON 403 keeps `error` and `ability` but
  drops `module`. The `authz.failed` event payload gains `unauthenticated`.
- The denial callable keeps its `(array $context, string $ability, bool $undefined)` signature;
  a signed-out refusal is marked with `$context['unauthenticated'] = true`.
