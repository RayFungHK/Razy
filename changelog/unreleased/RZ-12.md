# RZ-12: dist request-resolver stage (host/tenant) before routing

## Added
- A request-resolver stage on every dist. A module registers with
  `$agent->resolveRequest(fn (RequestContext $request): ?Response => …)`. Resolvers run once per
  request (worker mode included), after the module lifecycle is ready and the session is started,
  and before the route table, in module load order; one per module (registering again replaces it).
  Return null to route the request, or a `Razy\Http\Response` to end it: the response is sent and
  no later resolver or route runs. Any other return value throws `UnexpectedValueException`;
  exceptions are not caught and reach the dist's error page.
- `Razy\Http\RequestContext`: `host()` (trusted proxies applied), `method`, `path` (dist-relative),
  the `request` (`Razy\Http\Request`), and an attribute bag (`set`/`get`/`has`/`all`) that resolvers
  fill and controllers read with `$this->requestContext()->get('tenant')`. A fresh context is
  built for every request, so attributes never carry over in worker mode.
- `Razy\Http\Response` (status, body, headers; CR/LF/NUL in header values and bad header names
  throw), with `Response::notFound()` and `Response::redirect($location, $status = 302)`. Headers
  are sent after the dist's security headers (RZ-10) and replace a same-name header.
- `Controller::requestContext()`, `Module::getRequestContext()`, `Module::addRequestResolver()`,
  `Distributor::getRequestContext()`, `Distributor::getRequestResolver()`.

## Migration
- Host or tenant checks that run database I/O or `exit` in `__onInit` (an RZ-009 violation, and
  fatal to a worker) move into a resolver: record the tenant with `$request->set()`, and return
  `Response::notFound()` instead of printing and exiting. Under `'compiled_boot' => true`, register
  the resolver in `__onLoad` (a compiled boot does not re-run `__onInit`).
- Nothing changes for a dist with no resolver.
