# RZ-25: active files under /data are not rendered on the app origin

## Security
- `php Razy.phar serve` (`src/asset/setup/serve.php`) served `/data` inline.
  `.html` / `.htm` and a file libmagic called `text/html` were `text/html`.
  SVG was `image/svg+xml`. A user upload on that URL was stored XSS on the
  app origin. Those responses now send `Content-Disposition: attachment`
  and `Content-Security-Policy: sandbox`. `X-Content-Type-Options: nosniff`
  stays on every `/data` response.
- The same attachment, sandbox, and nosniff headers are on the generated
  Caddy data handle and the Apache data mapping, for one shared extension
  list (any case). The list is every extension in Apache httpd
  `mime.types`, the system `mime.types` Go loads, or Go's builtin MIME
  table that maps to `text/html`, `application/xhtml+xml`,
  `image/svg+xml`, a `*/xml` or `+xml` type, or a JavaScript type.
  `.cjs` is on that list as well: it is the CommonJS name beside `.js`
  and `.mjs`, and neither table maps it. The list includes `shtml`,
  `ehtml`, `xht`, `xhtm`, `xsl`, `xslt`, `rdf`, `mathml`, `mml`, `xbl`,
  `svgz` and `es`. `file_server` still sends bytes. It does not run PHP.
- The generated Apache data mapping does two things. A real `.php`,
  `.phtml` or `.phar` under that mapping is bytes: the rule matches an
  extension followed by `/` or the end, so `/data/note.php/extra` is the
  file and not PATH_INFO into the PHP handler. `[H=default-handler]`
  (the per-rule form of `SetHandler none`) covers the whole mapping.
  `RemoveHandler` runs when the rewrite env is visible. That env is set
  only when a path follows `data/`, so the directory URL `/data/` still
  reaches the front controller. The script response is
  `Content-Type: application/octet-stream`. The same active extensions
  get the attachment, sandbox, and nosniff headers. The marker and the
  file publish rule are both case-insensitive, so a case variant of the
  prefix is that file, not the application response wearing those
  headers. `[END]` stays, so the rewrite does not re-enter and hand the
  file to `index.php`.
- On `php -S` and on the generated Caddy data handle, `/data/note.php/extra`
  is that file's bytes, or 404 when the file is absent. It does not fall
  through to PHP. Caddy keeps the URL inside `file_server`.
- A directory URL under the data mapping does not publish `index.html`.
  Caddy `file_server` uses `index ""` (no index file) and `hide` for the
  default names `index.html` and `index.txt`, so `/data/` and
  `/data/uploads/` are not that document. A direct request for those two
  names is 404 on Caddy. Any other basename still downloads. Apache sets
  `DirectoryIndex disabled` and `Options -Indexes` only for the mount
  (`^/data` or `^/shop/data`, and the same path under `CONTEXT_PREFIX`
  for a subdirectory install). `/data/` itself still reaches `index.php`.
  `/database` and `/report/data/export.php` are outside that `<If>`.
  `php -S` returns 404 for `/data/` and `/data/sub/`, including when
  `index.html` is present. Requesting that file by name still downloads.
- On `php -S`, libmagic also quarantines a renamed upload: a non-active
  extension whose type is `text/html`, a `*/xml` or `+xml` type, or a
  JavaScript type (`text/javascript`, `application/javascript`,
  `application/ecmascript`, and the `x-` forms), parameters ignored, gets
  the same two headers. Apache and Caddy match the extension. They do not
  run libmagic per request.

## Changed (breaking, security)
- An HTML, SVG, XML, XHTML, JavaScript, or other active-type file that used to render or run from
  `/data/...` now downloads, and a browser that ignores
  `Content-Disposition` still has `Content-Security-Policy: sandbox`
  (unique origin, no scripts). Images, text, and other non-active types
  are unchanged.

## Migration
- Regenerate: `php Razy.phar rewrite <dist>` and `php Razy.phar rewrite --caddy`.
  The checksum watchdog would force the Apache file on the next request anyway.
- There is no switch to keep serving those types inline from `/data`. That
  was the stored-XSS path. Trusted HTML belongs on an application route,
  with that route's own response headers.
- The Apache rules need Apache 2.4 or newer (`[END]`, `<If>`, the `H` and
  `T` flags) and `mod_headers` (`Header set ... env=`). A server without
  `mod_headers` will refuse this `.htaccess` until the module is loaded.
  `DirectoryIndex` and `Options` in that file also need `AllowOverride`
  to include `Indexes` and `Options` (or `All`).
- Not changed here: a hand-written Caddyfile that does not use the generated
  data handle. Copy the generated handle if that tree is on the public URL.
