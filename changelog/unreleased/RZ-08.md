# RZ-08: env/config layer

## Added
- `.env` is loaded at boot, before config.inc.php: `RAZY_ENV_FILE` (absolute, or relative to
  SYSTEM_ROOT; `none` disables), else `SYSTEM_ROOT/.env` when present. Variables already in the
  process environment always win. A missing `RAZY_ENV_FILE` target or an unparsable file stops
  boot (CLI: message on stderr, exit 1; web: generic 500, details in the error log).
- `Razy\Config\RuntimeConfig::loadEnv()` / `loadConfig()` (the boot steps above, testable).
- Typed env getters on `Razy\Env`: `string()`, `int()`, `bool()` (true/false/1/0/yes/no/on/off),
  `list()`, and `requireAll([...])`, which names every missing key in one
  `ConfigurationException`. A getter without a default makes the key required.
- `Database::fromUrl($url, $name = 'main')`: connect from `postgresql://`, `mysql://`,
  `sqlite:///path` or `sqlite::memory:` URLs and register the instance for
  `getSharedInstance($name)`. `Database::parseUrl()` exposes the parse. Options: `sslmode`,
  `connect_timeout`, `application_name`, `charset` (pgsql), `charset` (mysql); anything else is
  rejected. Errors never include the password.
- `PostgreSQL::buildDsn()` passes `sslmode`, `connect_timeout` and `application_name` through.

## Changed
- The setup `index.php` (and the one `php Razy.phar serve` generates) no longer evaluates
  config.inc.php before loading the phar. It finds the phar via `RAZY_PHAR`, else next to
  `index.php`, and only reads `phar_location` from config when the phar is not there.
  The framework then evaluates config.inc.php after `.env`, so config can call
  `\Razy\Env::string()` / `\Razy\env()` on `.env` values.
- config.inc.php is now also evaluated in CLI mode (it was web-only).

## Migration
- Existing `index.php` files keep working: the config they read before the phar is used as is
  (never evaluated twice). To read `.env` values inside config.inc.php, replace `index.php`
  with the new setup template. `.env` values are visible to application code either way.
