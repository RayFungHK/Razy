# RZ-14: request id, structured log context, JSON stderr logs

## Added
- `Razy\Http\RequestId`: every web request (worker mode included) gets an id at the start of the
  request. A client's `X-Request-ID` is kept when it is 1-128 chars of `[A-Za-z0-9._:-]` and the
  accept policy allows it; otherwise a 32-hex id is generated. The id is sent back in the
  `X-Request-ID` response header. Policy: `RAZY_REQUEST_ID_ACCEPT` env, else config.inc.php
  `request_id_accept`: `any` (default), `trusted_proxy` (only through a trusted proxy, RZ-04) or
  `none`. API: `begin()`, `current()`, `generate()`, `isValid()`, `policyFromConfig()`, `reset()`.
- `Razy\Log\LogContext`: request-scoped fields (`set`/`get`/`remove`/`all`/`apply`/`reset`) merged into
  every `Razy\Logger` and `Razy\Log\LogManager` record's context; the log call's own keys win. It
  holds `request_id` and is cleared at the start of each request.
- `Razy\Contract\Log\LogFormatterInterface`, `Razy\Log\LineFormatter` (the existing text line) and
  `Razy\Log\JsonFormatter` (one JSON object per line: `ts`, `level`, `channel`, `message`,
  `request_id`, `context`, `exception`).
- `StderrHandler::__construct($minLevel, ?LogFormatterInterface $formatter = null, $stream = null)`
  and `getFormatter()`. It now opens `php://stderr` when the `STDERR` constant is missing (FPM,
  FrankenPHP) instead of failing.
- `Razy\Log\RuntimeLogging`: `RAZY_LOG_FORMAT=json` (or config `log_format`) installs a JSON stderr
  logger for framework error reports when the app has not set one with `Error::setLogger()`.
  `RAZY_LOG_LEVEL` / `log_level` sets its level (default `info`).
- `Razy\Http\HttpClient` sends the current request id as `X-Request-Id` unless the call sets one.
- `RequestContext::requestId()`.

## Changed
- Text log lines (`Logger` files, `FileHandler`, `StderrHandler`) and the `error_log()` fallback of
  `ErrorReporter` end with ` rid=<id>` when a request id is set. Log parsers that anchor on the end
  of the line need to allow the suffix. CLI runs have no request id and are unchanged.
- `Logger`/`LogManager` buffer entries include the `LogContext` fields in `context`.
