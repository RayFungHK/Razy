# RZ-35: module versions per distributor

## Added
- dist.php `modules` pins are honoured. Before RZ-35 the pin was read and
  dropped (`Distributor::parseModuleRequirements` stored `null`), so every
  dist loaded `default/`. Now each dist loads the version it pins:
  - not pinned: `default/`; a module with no `default/` is not loaded (unchanged);
  - a folder name (`'default'`, `'dev'`, `'1.4.0'`): that folder;
  - `'*'`: the highest version folder, else `default/`;
  - a semver range (`'^1.4'`, `'~2.0.0'`, `'>=1.0 <2.0'`, `'1.4.*'`, `'^1 || ^2'`):
    the highest version that satisfies it.
  `default/` takes part in range matching with the `'version'` its package.php
  declares; a numbered folder wins at the same version.
- The `'*'` set is the base and the dist tag's set (`sites.inc.php`
  `'mysite@canary'`) overrides or adds entries, as the docs described. A module
  code at the top level of `modules` counts as part of `'*'`.
- `Razy\Distributor\ModuleVersionResolver` (resolution) and
  `Razy\Distributor\ModuleVersionGuard` (one version per process);
  `Razy\Exception\ModuleVersionException` (extends `ModuleLoadException`).
- `ModuleInfo::getVersionFolder()`: the folder the module loaded from.

## Changed
- A pin that matches no version folder stops the boot with
  `ModuleVersionException`, listing the folders found. Before RZ-35 such a pin
  silently loaded `default/`.
- A pin naming a module that no folder has prints an `E_USER_WARNING`.
- A pin that is not a string (or a number) is a `ConfigurationException` at boot.
- package.php `'require'` constraints are checked before any `__onInit` runs.
  If the loaded version of a dependency does not satisfy a constraint, the boot
  stops with one `ModuleVersionException` that lists every conflict. `''` and
  `'*'` always hold; a dependency with no semver version (an undeclared
  `default/`) is not checked. Missing dependencies keep the L0 warning.
- One PHP process loads one version of a module. A second dist in the same
  process (worker mode keeps classes across requests) that needs another
  version is refused before its code loads, with an error naming both dists.
  Serve dists on different versions from separate processes (worker pools), and
  restart workers after changing a pin. `scanModules()` (the `rewrite` command)
  loads no module code and is not limited.
- `ModuleInfo::getVersion()` and `Controller::getModuleVersion()` return the
  semver number: the numbered folder, or the `'version'` a `default/` or `dev/`
  package.php declares. With none declared they still return the folder name.
  Webasset URLs and the compiled boot keep using the folder (`getVersionFolder()`),
  so `webassets/<alias>/default/` URLs do not change.
- A numbered version folder whose package.php declares a different `'version'`
  is a `ModuleConfigException`.
- `VersionUtil::vc()` follows Composer for caret and tilde ranges: `^0.2.3` is
  `>=0.2.3 <0.3.0` (before: matched nothing), `~2.0.0` is `>=2.0.0 <2.1.0`
  (before: matched nothing), `~1.2.0` is `>=1.2.0 <1.3.0` (before: `<2.0.0`).
  A bare `'*'` matches any version (before: false). This also applies to
  package.php `prerequisite` checks and `PackageManager` constraints.
- `php Razy.phar set -i` writes the `modules` block as `'*' => [...]`.

## Migration
- Dists that pin nothing, or pin `'default'` or `'*'` for modules that have only
  `default/`, behave as before.
- Deprecation note: a pin used to be ignored. Check each dist.php `modules` entry:
  - a pin such as `'1.0.0'` for a module that has only `default/` now loads
    `default/` only if its package.php declares `'version' => '1.0.0'`;
    otherwise the boot stops. Pin `'default'`, or declare the version;
  - `'*'` now loads the highest numbered folder when the module has one, not `default/`;
  - a package.php `'require'` whose constraint the dependency's declared version
    does not meet now stops the boot. Fix the constraint or the version.
- Code that compared `getVersion()` / `getModuleVersion()` with `'default'` gets
  the declared version when `default/package.php` declares one; use
  `getVersionFolder()` for the folder.
- Code that needs two versions of a module at once (two dists, one worker
  process) must move one dist to its own worker pool.
