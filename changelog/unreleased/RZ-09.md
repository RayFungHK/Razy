# RZ-09: content-hashed asset URLs, an ES module importmap, and a safe static file server

## Added
- Template function `{@asset file='js/app.js'}` (optional `module='alias'`; default: the module
  that loaded the template) prints the asset URL with `?v=<content hash>`, HTML-escaped. It keeps
  the `getAssetPath()` layout (`/webassets/{alias}/{version}/{file}`), so the generated rewrite
  and Caddy rules serve it unchanged. One URL per file; it changes only when the content does.
  The named form is required (the engine's positional parameter form does not reach plugins).
- Template function `{@importmap}` prints `<script type="importmap" nonce="…">` mapping every
  `.js`/`.mjs` file of the dist's running modules from its plain URL (what a relative `import`
  resolves to) to its hashed URL, so a module is evaluated once however it is imported. The nonce
  is the request's CSP nonce (RZ-10). For a hash-based CSP, `Assets::importMapHash()` returns
  the `'sha256-…'` source.
- `Razy\Asset\Assets`, configured by dist.php `'assets'` and validated at boot (unknown keys and
  bad values throw `ConfigurationException`): `serve` (bool), `max_age` and `immutable_max_age`
  (seconds), `base_url` (URL prefix, e.g. a CDN), `imports` (`[specifier => 'alias/path.js']`
  bare specifiers for the importmap). Methods: `url()`, `importMap()`, `importMapJson()`,
  `importMapHash()`, `importMapTag()`, `match()`, `serve()`, `current()`/`setCurrent()`,
  `moduleRoots()`. `Distributor::getAssets()` and `Standalone::getAssets()`.
- `Razy\Asset\AssetManifest`: a module webassets folder's content hashes (xxh128, 16 hex digits,
  cached per process by path, mtime and size) and file listing.
- `Razy\Http\StaticFile`: `resolve($root, $urlPath)` is a traversal guard (one URL decode; no null
  byte, backslash, `%`, `.`/`..` or dotfile segment; realpath must stay under the root, so
  symlinks out of it are refused). `contentType()` maps extensions (JS is `text/javascript`,
  unknown is `application/octet-stream`, never sniffed). `response()`/`send()` set `ETag`,
  `Last-Modified`, 304 on `If-None-Match`, and `Cache-Control: public, max-age=31536000,
  immutable` only when the request's `v` equals the current hash.

## Changed
- With `'assets' => ['serve' => true]`, a dist answers `GET`/`HEAD /webassets/{alias}/{version}/{file}`
  in PHP, before the session and the route table (the version must be the running one). Off by
  default, so existing dists behave as before; on by default under PHP's built-in server
  (`php Razy.phar serve`), where nothing else serves module assets.
- The dev router (`serve.php`) no longer resolves webassets itself (it expected
  `/webassets/{vendor}/{module}/{version}/…`, which `getAssetPath()` never produces); those
  requests reach the app. It also sets `SCRIPT_NAME` to `/index.php` before handing over: PHP's
  built-in server reports the request path there when it has an extension, which the bootstrap
  took for a subdirectory install (`/webassets/app/default/js/a.js` reached the app as `/a.js`).
  Its `/data/` mapping uses the same realpath guard, and JS is sent as `text/javascript`.
- Generated Caddyfile: the webassets handler maps `/webassets/{alias}/{version}/{file}` to
  `{module}/{version}/webassets/{file}`. It used to strip only the alias and serve
  `{module}/{version}/{file}` — the wrong folder, which also exposed the module's PHP source
  (`package.php`, `controller/`) as plain text. Regenerate with `php Razy.phar rewrite --caddy`.
