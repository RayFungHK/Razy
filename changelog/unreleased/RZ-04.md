# RZ-04: trusted proxies, Request facts, canonical origins, RAZY_DOMAINS

## Added
- `Razy\Http\TrustedProxies`: proxy IPs / CIDR blocks (IPv4 and IPv6) whose
  `X-Forwarded-Proto/-Host/-Port/-For` headers are believed. Configured from
  `RAZY_TRUSTED_PROXIES` (env, wins) or config.inc.php `'trusted_proxies'`; `*` trusts every peer.
- `Razy\Http\Request` with `scheme()`, `isSecure()`, `host()`, `port()`, `clientIp()` (rightmost
  untrusted X-Forwarded-For hop), `origin()`, and `Request::normalizeOrigin()`.
- dist.php `'origin' => 'https://app.example.com'`: the dist's canonical origin.
  `Distributor::getSiteURL()` builds absolute URLs from it instead of the request Host;
  `Distributor::getCanonicalOrigin()` exposes it. Invalid values are a boot error.
- `Razy\Config\DomainList::fromEnv()/parse()` lets sites.inc.php build its `domains` table from
  `RAZY_DOMAINS` (`host`, `*.host`, `host:port`, `host=dist[@tag]`).

## Changed
- `NetworkUtil::ipInRange()` supports IPv6 (families never cross-match).
- `NetworkUtil::isSsl()` compares `SERVER_PORT` as an integer (the old `443 === '443'` check
  was never true) and reads `X-Forwarded-Proto` only from trusted proxies once any are configured.
- `NetworkUtil::getIP()` returns the client from X-Forwarded-For when REMOTE_ADDR is a trusted
  proxy; otherwise REMOTE_ADDR as before.
- Behind a trusted proxy, `HOSTNAME`/`PORT` (and thus domain matching and `SITE_URL_ROOT`)
  use the forwarded public host and port. `SITE_URL_ROOT` omits port 443 as well as 80.

## Deprecated
- With **no** trusted proxy configured, `isSsl()` still honours `X-Forwarded-Proto: https` from
  any peer (the pre-RZ-04 behaviour) and logs a deprecation once per process. Set
  `RAZY_TRUSTED_PROXIES` to opt into strict mode now; the fallback goes away in the next major.
