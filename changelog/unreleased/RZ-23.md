# RZ-23: classic FrankenPHP is no longer detected as worker mode

## Fixed
- `WORKER_MODE` was `true` whenever `frankenphp_handle_request()` existed. Classic FrankenPHP
  (`php_server` without a `worker` directive) has that function too, so such an app was booted as
  a worker, and calling the function outside a worker throws. Worker mode now needs FrankenPHP's
  worker marker (`FRANKENPHP_WORKER`, which FrankenPHP sets for worker scripts; read from
  `$_SERVER`, else the environment) together with `frankenphp_handle_request()`, or the existing
  `CADDY_WORKER_MODE=true` opt-in. Classic FrankenPHP now takes the per-request path. Real workers
  and FPM / `php -S` / CLI behave as before.

## Added
- `Razy\RuntimeMode::detectWorker(array $server, bool $hasHandleRequest, string|false
  $caddyWorkerMode = false, string|false $frankenphpWorkerEnv = false): bool`, the rule above.

## Changed
- `bootstrap.inc.php` defines `CLI_MODE`, `WEB_MODE` and `WORKER_MODE` only when they are not
  already defined. Defining one in the entry script before the phar boots is the supported
  override (`define('WORKER_MODE', false);`); before, it raised "Constant already defined".

## Migration
- None. An app that predefined `WORKER_MODE` and silenced the "already defined" warning can drop
  the silencing.
