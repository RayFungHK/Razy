# RZ-11: shared layouts across modules; a missing INCLUDE throws

## Added
- `@layout/…` paths. `<!-- INCLUDE BLOCK: @layout/head.tpl -->` and
  `$this->loadTemplate('@layout/page')` read from the dist's shared layout folder, so several
  modules can share one head / chrome / foot without reading each other's `view/` folders.
  The folder is dist.php `'templates' => ['layout_path' => …]` (default `layout/` next to
  dist.php; standalone apps use `layout/` in the app folder). A resolved file must stay inside
  that folder after `realpath`, so `@layout/../x` and symlinks out of it fail.
- `Razy\Template\IncludeResolver`, `Template::setIncludeResolver()` / `getIncludeResolver()`.
  dist.php `'templates'` is validated at boot (unknown keys and wrong types throw
  `ConfigurationException`).

## Changed
- An INCLUDE path that does not resolve now throws `TemplateException` (it used to be skipped
  silently). `'templates' => ['strict_include' => false]` restores the skip with an
  `E_USER_DEPRECATED` notice; that switch goes away in the next major.
- More than 256 INCLUDEs while parsing one template throws, so an include cycle fails instead
  of looping.
