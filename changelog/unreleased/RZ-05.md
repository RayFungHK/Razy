# RZ-05: one session subsystem

## Added
- dist.php `'session'`: driver (`file` default, `database`, `redis`, `array`) and cookie options
  (`name`, `lifetime`, `path`, `domain`, `secure` = `'auto'`|bool, `http_only`, `same_site`,
  `gc_max_lifetime`). Validated at boot; unknown keys are errors.
- `Distributor::getSession()`: the dist's one session. It is mounted on every route when the dist
  configures `'session'` or arms CSRF, and bound on the container as `SessionInterface` / `Session`.
- `Razy\Session\SessionFactory` (build from config) and `Razy\Session\SessionDoor` (mount + bind).
- `SessionConfig::fromArray()` and `SessionConfig::resolveSecure()`.
- `Session::storageKey($id)`: lowercase sha256 hex of the cookie value.

## Changed
- **Token format.** New session ids are 64 hex (32 random bytes); drivers store a session under
  `sha256(cookie)` hex, never the cookie itself. A service sharing the store looks a session up
  with `sha256(cookie)` (Python: `hashlib.sha256(token.encode()).hexdigest()`).
  Pre-RZ-05 40-hex cookies are still accepted: their raw-keyed row is read once, rewritten
  under the hashed key on `save()`, and the raw row is then deleted.
- `SessionConfig::$secure` is `?bool`, default `null` = Secure when the request is HTTPS
  (trusted proxies included, RZ-04). It was `false`. Pass `secure: false` to keep the old flag.
- The CSRF door uses the dist session instead of a private file-backed one, so CSRF tokens and
  application session data share one cookie and one store.
- `DatabaseDriver` writes JSON rows (readable outside PHP); rows written with `serialize()` still read.
  Data JSON cannot carry (invalid UTF-8, INF/NAN) falls back to `serialize()` rather than losing the write.
- Database sessions default to a per-dist table `razy_sessions_<dist>` (rows are keyed by
  sha256(cookie) alone, so a shared table would let two dists read each other's sessions). Set
  `database.table` to share one with another service.
- Database and redis session drivers are built on first use (`LazyDriver`), so boot and CLI
  introspection open no connection and run no DDL.
- A session object reused across requests (worker mode) starts clean when the request changes or
  the browser sends a different cookie; reopening in the same request (including after
  `regenerate()`) resumes.

## Migration
- Existing sessions survive the upgrade (40-hex migration above). Code that read a driver with the
  raw id must use `Session::storageKey($id)`.
