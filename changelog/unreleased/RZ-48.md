# RZ-48: razymod/apps and razymod/permissions boot on a real distributor

## Fixed
- Both modules failed to load on a real distributor; their tests mocked `Agent` and required the api/ closures
  directly, so nothing booted them. Three causes, each now pinned by `tests/RazymodBootTest.php`, which boots both
  modules on a real `Module` and `Agent` (only the Distributor is a stub), checks every registered command and runs
  one command each through the real command registry and the distributor's own module autoloader:
  - The controller file returned a named instance (`new AppsController()`), and `Module::buildController()` accepts
    only an anonymous class (`ModuleLoadException`). The files now return `new class () extends AppsController {}`
    (same for `PermissionController`): the framework keeps its one controller-file form (docs/STYLE.md §4), and the
    named class still types `$this` in the api/ closures for PHPStan.
  - Hyphenated command names were refused by `Agent::addAPICommand()` (`/^#?[a-z]\w*$/i`). Renamed to camelCase:
    `assign-ids` → `assignIds` (apps); `can-any` → `canAny`, `define-ability` → `defineAbility`, `roles-of` →
    `rolesOf`, `assign-role` → `assignRole`, `revoke-role` → `revokeRole`, `audit-actor` → `auditActor`
    (permissions). API.md, the manual and the architecture doc follow.
  - `razymod/permissions` never loaded `support/Service.php` (only the tests did), so `service()` died with
    "class not found"; the controller now requires it.

## Added
- RZ-018 also fails an API or bridge command name the Agent would refuse at boot.

## Changed
- `razymod/apps` 0.2.0 and `razymod/permissions` 0.3.0 (0.x minor: the command names changed). Callers using the
  old names never reached a booted module; no in-repo or known consumer calls them.
