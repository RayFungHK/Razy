# RZ-42: the style reference, checked

## Added
- `docs/STYLE.md`: Razy's conventions in one place. It opens with the founding rule — a module is owned by one
  team or person, and its published API and API doc are the contract; nobody edits another owner's module files,
  change requests go through the owner. Then: one naming rule (PSR-1 camelCase methods; the static-PascalCase
  rule is retired), one operator table for every DSL, values only through `:name`, the plugin file contract,
  module layout and version folders, typed errors, size caps (file and class 400 lines, function 60), file
  hygiene, static analysis, and a table of which tool checks which rule.
- Golden Rule **RZ-018** (`tools/lint-module-discipline.php`): every module's `module.php` names an `'owner'`, an
  `API.md` sits beside it, and every `addAPICommand` / `addBridgeCommand` / `trigger` name in the module's live
  code is documented there.
- Golden Rule **RZ-019**: a value concatenated or interpolated into a query-builder syntax string (`where`,
  `orWhere`, `having`, `order`, `select`, `from`, `update`, `delete`) is an error; a spliced identifier from the
  code's own configuration carries `lint-allow: RZ-019 <reason>`. Patterns in `tools/lint/rz019.php`, shared by
  both lints.
- `tools/lint-style.php` (`composer lint-style`, part of `composer quality`, CI step "Framework style lint"):
  STY-NAME, STY-FILE, STY-CLASS, STY-FUNC, STY-STRICT and RZ-019 on `src/library/Razy`. Code that broke a STY
  rule before it existed is listed in `tools/style-baseline.json`; it may stay, may not grow, and a fixed entry
  is reported so the baseline only shrinks.
- `'owner'` in all 33 in-tree modules (`modules/`, `demos/`, `demo_modules/`) and an `API.md` for each, written
  from the registered commands, their closure signatures and gates.
- CI runs `lint-module-discipline.php --self-test` (RZ-018 / RZ-019 fixtures included).
- `CLAUDE.md` pointing at `AGENTS.md` and `docs/STYLE.md`.

## Changed
- PHPStan no longer ignores "Call to an undefined method" / "Access to an undefined property" wholesale, in
  `phpstan.neon` or `phpstan.modules.neon`. The 7 call sites that still need it are listed one by one in
  `phpstan-baseline.neon` (five `Controller::__onPackage*` hooks called through `Module`,
  `SkillsGenerator::$sitesPath`, `ValidationRuleInterface::passed()`); any new one fails.
- `.php-cs-fixer.dist.php` names `indentation_type` explicitly (it was already on through `@PSR12`).
- The 14 framework lines that splice a model's primary key, a relation's key columns or the deprecated
  `Database::max()` identifiers into syntax strings carry a written `lint-allow: RZ-019` reason.

## Compatibility
- A project that runs `lint-module-discipline.php` on its own modules now gets RZ-018 errors until each module
  has `'owner'` and an `API.md`, and RZ-019 errors for values glued into syntax strings. Neither changes runtime
  behaviour: `'owner'` is not read at boot.
