# RZ-27: one layout per site, named anchors, and a loud error for the RZ-26 pattern

## Added
- `dist.php 'layout'`: the site layout (`'site'` = `@layout/site.tpl`, or an `'@layout/…'` path).
  `Controller::render(string $view, array $parameters = [])` renders a module view into it, at the
  reserved anchor `content`, and prints the page. `Template::renderPage(Source $page)` returns the
  same as a string.
- `{@anchor name="…"}` prints a named anchor; `{@push to="…" key="…" order=N}…{/push}` adds markup
  to it from anywhere in the response. Anchors are filled when the outermost render finishes, so a
  head anchor printed before the page body receives the body's pushes. Duplicates are dropped by
  `key`, else by the first `src` / `href`. Pushed scripts and module preloads get the CSP nonce;
  inline scripts can be pushed only as `importmap` or `application/json`.
- `Razy\View\Anchors` (`Template::anchors()`): `define`, `marker`, `push`, `setContent`,
  `claimImportMap`, `finalize`, `unresolved`, `reset`. Markers carry a random token per response,
  and only that exact token is replaced. The Distributor resets the anchors on every request
  (worker mode).
- `Entity::getManager()`, `Block::getSource()`, `Source::getManager()`, `FileReader::where()`.

## Changed
- `{@importmap}` prints once per response; a second call prints nothing.
- `Source::output()` and `Template::outputQueued()` replace this response's anchor markers when
  they are the outermost render. Templates without `{@anchor}` render exactly as before.

## Changed (breaking)
- RZ-26: a structural block comment (`INCLUDE`, `START`, `END`, `TEMPLATE`, `WRAPPER`,
  `RECURSION`, `USE … BLOCK`) while an enclosing function tag such as `{@if}` is open is now a
  `TemplateException` that names both lines. Before, the include always rendered and the closing
  tag was silently dropped, so the condition did nothing.

## Migration
- Templates that hit the new error had a condition that never worked. Move the condition into the
  included file, render the markup as a block, or push it with `{@if …}{@push …}…{/push}{/if}`.
  See `manual/13-layouts-and-anchors.md` §5.
- No change is needed to adopt nothing: without `'layout'` and without `{@anchor}`, output is
  unchanged.
