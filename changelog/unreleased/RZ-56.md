# RZ-56: exact routes and the dist's not-found answer

## Added
- `Route::exact()` / `isExact()`: the route matches only its own path, never a longer URL. Works on `addRoute` and `addLazyRoute`, chains with `can()`, `method()`, `ready()` and the other flags, and survives a compiled boot. Routes without it keep the prefix semantics (unchanged).
- `Agent::onNotFound(fn (RequestContext $request): Response)`: the dist's answer to a request no route matched. The Response is sent with status 404 whatever status it carries, after the dist's security headers, with no body for `HEAD`. One module per dist owns it. Without a handler the answer is `Error::show404()` as before. Works for a dist and for a standalone app. Register it in `__onLoad`: the boot compiler refuses an `onNotFound()` made in `__onInit`, which a compiled boot does not re-run.
- `Razy\Http\NotFoundHandler` (the dist's handler slot, `Distributor::getNotFoundHandler()`).
- `Razy\Exception\DomainNotMatchedException` (a `ConfigurationException`): thrown by `Application::host()` for a host not in `sites.inc.php`.

## Changed
- A request whose host is not in `sites.inc.php` gets the plain 404 page from the web front controller, not a 500 configuration page with debug details. CLI commands still fail with the exception.
- The compiled-boot artifact schema is `compiled-boot-2` (route specs carry `exact`). An artifact from an older build is stale and the dist boots in full until `php Razy.phar compile <dist>` is run again.

Manual: `manual/03-routing-and-requests.md` §1, `manual/08-coexistence.md` FM-2.
