# RZ-21: no consumer-app specifics in the framework

## Changed
- `Application::updateSites()` registers every `*.apex` binding in `sites.inc.php` as written. It used
  to drop the binding when the dist was named `default`, `personal` or `localhost`, or when the apex
  was local (`*.localhost`, `*.app.local`): one application's tenant policy, applied silently. A site
  config that lists `*.localhost` now routes those hosts to its dist. Wildcards are checked before the
  bare `*` fallback, so a host such as `foo.localhost` that used to fall through to `*` now matches
  `*.localhost` when both are listed. Exact hosts still beat one-label wildcards.
- `XHR::sendData()` docs call its body the Razy JSON envelope; the shape is unchanged.
- Comments, the routing manual, tests and an old changelog example no longer name a consumer app;
  `tests/LayerBoundaryTest.php` fails if one comes back.

## Deprecated (removed in v1.3)
- `NetworkUtil::RESERVED_LEFT_LABELS`, `NetworkUtil::isReservedLeftLabel()`,
  `NetworkUtil::isOneLabelSlug()`, `NetworkUtil::allowsApexWildcardSeed()`. They still work.
  `NetworkUtil::leftLabel()` and `NetworkUtil::isLocalOrDefaultHost()` stay.

## Migration
- Tenant naming (reserved labels, slug rules, which hosts may be a tenant) is app policy: keep the
  list in the app and check `NetworkUtil::leftLabel($request->host())` in a request resolver
  (`$agent->resolveRequest()`, RZ-12), returning `Response::notFound()` for hosts the app rejects.
- To keep a wildcard from reaching a dist, leave it out of `sites.inc.php`.
