# Razy v1.1.0-beta.2 — The One HTTP Door, an OAuth 2.0 Core With Nothing to Hide

**Release Date:** September 2026 (same-day sequel to v1.1.0-beta.1)  
**PHP:** 8.2+

The release that turned the OAuth/Socialite/HTTP dossier (`architecture/OAUTH-SOCIALITE-HTTP.md`,
maintainer sign-off Q1–Q5 all per recommendation) into shipped behaviour: every outbound HTTP
call in the framework now runs through ONE hardened door (`Razy\Http\HttpClient`), and the
long-advertised-but-never-wired `OAuth2`/`Office365SSO` pair is dead at the heart — replaced by a
real authorization-code core (`Razy\Security\OAuth\*`) with PKCE S256 always-on and signed
single-use state, plus a three-provider pack and the `razymod/oauth` route module. RZ-015 became
law mid-release: framework core carries zero third-party runtime dependencies, forever.
11 commits, suite 5,365 → 5,441 tests (+76). No breaking API changes; every disclosed behaviour
change is listed below.

---

## Highlights

- **Added** `Razy\Security\OAuth\*` (dossier S2, `c9c036c`): `OAuth2` flow core — `begin()`
  (PKCE S256 always-on, `plain` never offered or accepted; signed state), `exchange()` (state
  verified BEFORE any network call; provider error params mapped per RFC 6749 §5.2 only AFTER
  verification — an unverified error page is an attacker's page; single-use nonce redemption;
  exact-match registered `redirect_uri`, never derived from the request), `refresh()` (RFC 8707 —
  no PKCE on refresh grants); `StateSigner` (Q2 option C: HMAC-signed state bound to
  provider/redirect_uri/TTL, constant-time compares, PKCE-verifier custody in `Cache` with the
  verifier NEVER travelling through the browser, cacheless configuration fails loud);
  `TokenResponse` (relative `expires_in` lands as an absolute deadline), `OAuthConfig`,
  `ProviderInterface` + `ProviderRegistry`. Zero dependencies (RZ-015), zero network in tests
  (28 cases, RFC 7636 Appendix B vector pinned verbatim).
- **Added** provider pack (dossier S3, `a3b970e`): `GithubProvider` (UA-bearing user calls,
  verified+primary email fallback — email is CONTACT data, identity is `id`), `GoogleProvider`
  (`access_type=offline`, optional `prompt=consent`/`hd`; identity is **`sub`, not email**,
  `legacy_sub` still identifies), `MicrosoftProvider` (tenant-aware Entra endpoints, Graph
  field-selection, Graph object id as identity — not the UPN — plus sign-out URL).
  `OAuth2::verifyIdTokenClaims` enforces the G11 honest label in code: audience exact-match,
  absolute expiry, issuer regex, optional nonce/hd binds — it CHECKS STRUCTURE, it never verifies
  signatures (full JWK machinery stays on the dossier's Do-NOT-build list; say "claims checked",
  never "signature verified").
- **Added** `razymod/oauth` 0.1.0 (dossier S5, `56b49d6`): `/authorize` (302 — never the 301
  `Controller::goto`) and `/callback` (core-verified exchange → `social.user_resolved`); per-dist
  config carries ENV VAR NAMES only, never values (Q5); implemented `__onAPICall` allow-list
  publishing exactly one read-only `providers` command; `package.php` carries NO migration key —
  Q1 (no users table anywhere in framework/module) enforced as SCHEMA, test-pinned. Module
  discipline lint 0 errors/0 warnings. Companion docs: `manual/09-social-login.md`.
- **Added** HTTP one-door (dossier S1, `8b79947`/`177b935`/`0ffae09`): `HttpClient` hardened
  (HTTPS-only default with the `RAZY_ALLOW_INSECURE_TRANSPORT` operator escape, mandatory
  timeouts with a 1-second floor — cURL's "0 = forever" is unreachable by design, hard redirect
  cap of 3, `raw_body`/`sink`/`progress` request options, Content-Type-aware `data()` parsing);
  new `ClientInterface` (the injectable, fake-able, zero-network seam) +
  `HttpTransportException` (named transport causes, curl errno attached — the synthetic
  `HttpResponse(0, …)` era ends); migrated `publish.inc.php` ×10, `RepoInstaller` ×7,
  `RepositoryManager`, `PackageManager\HttpTransport`, and the `install`/`pkg`/`sync` download
  paths — each file pinned by `S1CallerMigrationTest`. Census: framework-wide `curl_init` now
  exists ONLY inside `HttpClient` and `SSE` (long-lived streaming, out of scope by decision) plus
  one `function_exists` environment probe.
- **Added** RZ-015 as law (`1d3b8cd`): framework core (`src/`) carries zero third-party runtime
  dependencies forever; PSR interop lives in modules/packages (ADR-1 in `PORTING-VALUE.md`,
  rule row in `AGENTS.md`/`skills/RAZY-AI-RULES.md`). This release's OAuth work shipped ~700 lines
  of new protocol code with `require: 0` unchanged — the law's first real test, passed.
- **Fixed** queue CLI silent-zero (`357d35d`): `queue work/once/status/clear/retry` without a
  registered-and-connected database now names the gap ("the CLI opens no connection itself —
  register AND connect one") and `exit(1)`s everywhere, store-construction failures surface class
  + message. A worker "running" forever against nothing while reporting success is structurally
  impossible now. 5 source-pinned tests.
- **Fixed** legacy `OAuth2`/`Office365SSO` (Q3: names kept, hearts replaced): both classes' cURL
  internals now run through the hardened door with messages preserved; urlencoded token answers
  (GitHub's DEFAULT shape) no longer die in `json_decode` in the legacy `getAccessToken` path.
  Their advertised-but-unwired status is now honestly labelled superseded in `CLASS-CATALOG.md`.
- **Fixed** doc phantom: `tests/Razy-Feature-TestCases.md` §48 documented a constructor
  (`new OAuth2()`) and array-parameter calls that never existed; corrected to real signatures in
  the S2 commit per the sign-off.

## Behaviour changes (all disclosed, all maintainer-decided)

- `HttpClient` enforces HTTPS unless `RAZY_ALLOW_INSECURE_TRANSPORT` is set in the environment
  (parity with the package-verification door); timeouts are mandatory (defaults 30/10 s, settable
  but floored at 1 s); redirects cap at 3 and are judged at the FINAL response.
- Transport failures raise `HttpTransportException` instead of returning a synthetic status-0
  response (zero production readers of status-0 existed; verified).
- `RepositoryManager` now NOTIFIES on unreachable repositories (previously a silent `null`).
- `PackageManager\HttpTransport` no longer short-circuits on the first status line of a redirect
  chain; a migrated download site's bare `HTTP 0` error line became a named cause.
- The `install` command's curl-LESS-environment stream fallback is preserved deliberately (the
  hardened client requires the extension).

## Upgrade notes

- Nothing to do to keep running. To adopt social login: set `RAZY_OAUTH_STATE_SECRET` in the
  environment (no default by design — a missing secret fails each login attempt loudly rather
  than silently weakening state), enable providers in `config/<dist>/oauth.php` with
  `client_id_env`/`client_secret_env` references, and register a `social.user_resolved` listener
  to own identity persistence (`manual/09-social-login.md`).
- `razymod/oauth` has no migrations and no storage — installing it changes nothing until a
  provider is configured.
- Custom `ClientInterface` implementations may now be injected anywhere the OAuth core or S3
  providers take an HTTP client; tests need no network and no fixtures beyond response shapes.
