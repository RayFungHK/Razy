# Razy v1.2.1 — The Release That Armed a Real Site, and the Two Machine Doors

**Release Date:** September 2026
**PHP:** 8.2+ (8.5-ready, matrix-pinned; floor raises to ^8.3 after upstream 8.2 EOL 2026-12-31)

A patch release that earned its patches the hard way: the armed CSRF door met a
production-shaped distributor and LOST — and losing is how the session layer learned
that an engine which mints its token before anyone can carry one is minting nothing.
On top of that fix, the two doors aimed at machines rather than browsers: a dist can
now be served to AI clients as an MCP server over its own bridge surface, and routes
can declare named abilities that fail closed. Suite 5,565 → 5,605. No breaking API
changes; the one behaviour change (session writes before `start()`) is a bug fix —
losing writes was never anyone's feature.

---

## Fixed — the armed-session bug, found live (the whole story is the lesson)

Arming a real distributor (`'csrf' => 'on'`) surfaced a session-layer defect that
every framework test had missed: a module minting its token at source level (the
supported `csrfToken()` pattern, manual/07) calls it during `__onReady` — which
fires **before** the CSRF door's session middleware runs. The session bag was
unstarted and therefore blind: it could not see the cookie it was carrying, so it
re-minted a fresh token on **every request** — the page rendered a token the next
request would not know. Every armed POST died 419 while every unarmed one sailed
through. The first fix (merging pre-start writes at `start()`) was treated-for-
symptom and made the re-mint *worse* (pending-write-wins then preferred the blind
new token over the stored one); it is recorded here, not quietly dropped.

The real fix is **lazy start**: `get/set/has/remove` each self-start the session
(idempotent), and `start()` ADOPTS pending pre-start writes by merging stored data
under them. Pinned by three RED-first tests (carried-cookie visibility, write-
before-start persistence, survives-`start()`), and manual/07's meta-recipe now
states the v1.2.0 consequence honestly rather than backdating good behaviour.

- `Session.php`: `start()` merge-under; `get/set/has/remove` self-start; docblock
  documents the lazy semantics. `save()` still no-ops unstarted; `regenerate()`
  untouched (verified safe under the new semantics).

## Added — MCP server (`php Razy.phar mcp <dist>`)

Serve one distributor as a Model Context Protocol server (2025-06-18, stdio): an AI
client discovers and calls the dist's **bridge commands** — the exact surface
`addBridgeCommand` + `__onBridgeCall` + `RAZY_BRIDGE_SECRET` HMAC already define. No
new door: whatever the server reaches, `php Razy.phar bridge` could already reach
(source identity `mcp-cli` = local-IPC operator trust, same standing as the bridge
CLI; with the secret set the server self-signs and the module-level HMAC
verification runs for real).

Tool metadata is READ from the handlers — first comment line as description,
reflection over the same `ClosureLoader` execution uses for the schema (`required`
= no default; builtin types mapped) — so no side registry can drift from the code.
Named JSON arguments bind by parameter name; a named hole before a given value is
refused by name, never silently shifted. A `null` bridge result reports
"unverified" rather than pretending to distinguish denial from no-answer.
stdout carries MCP messages only; the protocol core is transport-free and
unit-pinned (`McpServerTest`). Full dossier: `manual/10-mcp-server.md`.

## Added — AUTHZ-RAIL: `Route::can('ability')` + `Agent::addAuthzAbility()`

The declarative route gate the PERMISSION-MODULE dossier deferred: a route declares
an ability NAME, modules register predicates (RZ-009-clean, register-in-`__onInit`),
and a permanently mounted gate middleware answers — **inert on every dist that never
declares** (zero-BC), reading only the routed context (the `csrf_exempt` travel
shape, object-free), guarding every verb including GET page views.

**Fail-closed is the whole point**: an undefined ability or a throwing predicate
denies, and the 403 says so honestly (browser page + XHR JSON envelope in the
CsrfRejection dialect, `authz.failed` event for audit, request body never echoed).
The declaration survives compile/replay byte-identically (spec key `authz` +
dispatcher replay); `can('')` throws at registration (the csrfExempt posture:
unrepresentable beats warned-about). Policy stays where it belongs — the predicate
delegates to `Razy\Auth\Gate::allows()` or `api('razymod/permissions')->can()` at
the site's choice (wiring recipe: `manual/11` §10).

## Honesty notes (retractions this release owes)

- **Model casts were NOT missing.** The gap review that queued this release claimed
  casts/accessors absent; `Model::$casts` + `castGet/castSet` (int/float/bool/string/
  array-json/datetime, both directions) + `get{X}Attribute`/`set{X}Attribute`
  accessors ship complete since v1.2.0. The claim was wrong and is retracted here.
- **`Razy\Auth\{Gate,AuthorizeMiddleware}` have zero boot wiring** — verified by
  grep, not inferred. They remain a module-side opt-in; the AUTHZ-RAIL door is the
  first boot-mounted route gate, which is why `manual/11` §10 documents the bridge
  rather than leaving two undiscoverable halves.

## Upgrade

Drop-in. Nothing arms itself: session lazy-start only changes the fate of writes
that used to be silently lost; the authz door passes everything until a route
declares `->can()`; MCP is a CLI command you have to run. `php Razy.phar version`
on the release phar reads 1.2.1; dists keep working byte-identically until
`'csrf' => 'on'`.
